# TASK-052 — Голос: распознавание речи Whisper (voice-whisper)

## Цель

Локально превращать голосовые сообщения и аудиофайлы в текст, чтобы голосовой ввод из Telegram/Avalonia/CLI попадал в обычную маршрутизацию Tier 0–3 как текстовый запрос.

## Контекст

- Модели не встроены в продукт: локальная STT-модель (Whisper или совместимая) устанавливается/настраивается UI-инструментом (TASK-081) из каталогов (TASK-080); навык получает готовый движок через DI и до этого работает на фейковом движке.
- Голос — входной канал, а не отдельный пайплайн: результат распознавания публикуется как обычное текстовое сообщение по интерфейсам TASK-002.
- Эвристическая оценка риска аудио-контента — TASK-071: навык передаёт ей аудио/транскрипт при включённой политике и учитывает вердикт, но не реализует оценку сам и не применяет фиксированный Volume Clamp.

## Объём работ

- Реализовать (to-be-created, напр. `src/CyberPipe.Skills.Voice/`) навык `voice.transcribe` по контрактам TASK-002: вход — аудиопоток/файл (формат, длительность, язык-подсказка), выход — текст, язык, уверенность по сегментам, длительность обработки.
- Абстракция `ISpeechToTextEngine` с локальной реализацией (Whisper через локальный процесс/библиотеку, конфигурируемый путь и модель) и фейковой реализацией для тестов; движок запускается в изолированном рабочем процессе Brainstem (супервизор — TASK-022), а не в процессе Service.
- Нормализация входа: конвертация в 16 kHz mono WAV через конфигурируемый внешний конвертер (ffmpeg при наличии); неподдерживаемый формат — типизированная ошибка, а не падение.
- Лимиты из конфигурации (TASK-003): максимальная длительность и размер аудио (значения настраиваемые, по умолчанию — разумные локальные лимиты); превышение — `ValidationError` с причиной.
- Язык: автоопределение движком, подсказка `ru/en/auto` из запроса; пустой результат (тишина) возвращает пустой текст со статусом `NoSpeech`, а не ошибку.

## Вне рамок

- Синтез речи (TTS), установка моделей и выбор железа (TASK-081/TASK-082), каталоги моделей (TASK-080), эвристика безопасности аудио (TASK-071), супервизор Brainstem (TASK-022), захват микрофона в UI (TASK-061/TASK-060).

## Зависимости

- TASK-002

## Контракты и интерфейсы

- `voice.transcribe(AudioInput) -> TranscriptionResult { Text, Language, Segments[], Status: Ok|NoSpeech|ValidationError|EngineUnavailable }` по DTO TASK-002; аудио передаётся потоком/файловой ссылкой, не `byte[]` в памяти целиком для больших файлов.
- `ISpeechToTextEngine.TranscribeAsync(Stream audio, SttOptions, CancellationToken)`; недоступность движка/модели — `EngineUnavailable` с диагностикой, вызывающий код решает, что показать пользователю.
- Результат транскрипции далее обрабатывается как обычный текстовый запрос (интеграция с роутером — через сообщения TASK-002, без прямой зависимости от TASK-030..034).

## Результаты

- Проект голосового навыка (to-be-created) с локальным и фейковым движками, нормализацией аудио и лимитами из конфигурации.
- Запись навыка в реестре; транскрипт проходит в чат-пайплайн как текст.

## Критерии приёмки

- На фейковом движке навык возвращает детерминированный транскрипт и корректные метаданные; на локальном Whisper (при установленной модели) русская и английская фразы из тестовых фикстур распознаются с WER в пределах порога фикстуры.
- Тишина даёт `NoSpeech`, повреждённый файл — типизированную ошибку, превышение лимита длительности — `ValidationError`.
- Отсутствующая модель даёт `EngineUnavailable`, Service при этом продолжает работу.
- Отмена по `CancellationToken` останавливает распознавание и освобождает рабочий процесс.

## Тестирование

- Уровень: unit + component (+ ручной e2e на Windows). Unit — фейковый движок и фейковый конвертер; component — навык + реестр на моках каналов. Реальный Whisper проверяется отдельной маркированной категорией тестов (`Category=RequiresModel`), исключённой из обычного прогона.
