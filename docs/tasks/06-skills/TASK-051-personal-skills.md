# TASK-051 — Персональные навыки (notes/finance/reminders/crm)

## Цель

Дать владельцу (только Owner, роль Guest удалена) повседневные навыки: заметки, учёт финансов, напоминания и простую CRM (контакты и взаимодействия), вызываемые из чата/Telegram и цепочек.

## Контекст

- Одна PostgreSQL (TASK-010/TASK-011) — единственный источник данных; репозитории — TASK-013, здесь используются только их контракты из TASK-002 при наличии, иначе фейки репозиториев на период разработки.
- Напоминания по расписанию относятся к Quartz.NET (TASK-045) и триггерам (TASK-041); здесь реализуется доменная логика напоминаний, а регистрация расписания делегируется интерфейсу планировщика из TASK-002.
- Доступ только Owner: проверка владельца — TASK-073, навык лишь не обходит её и не хранит собственных списков доступа.

## Объём работ

- Реализовать (to-be-created, напр. `src/CyberPipe.Skills.Personal/`) навыки по контрактам TASK-002:
  - `notes.create/search/get/update/delete` (текст, теги, время);
  - `finance.add_expense/add_income/balance/report` (сумма, валюта, категория, дата; отчёт за период);
  - `reminders.create/list/cancel/complete` (текст, срок или Cron-выражение как строка — без собственной интерпретации Cron);
  - `crm.contact_upsert/find`, `crm.interaction_add/history` (имя, каналы связи, заметка о взаимодействии).
- Валидация аргументов: сумма > 0, валюта из настраиваемого списка (по умолчанию RUB/USD/EUR), дата напоминания не в прошлом; ошибки — типизированный `ValidationError`.
- Поиск заметок — текстовый (ILIKE/FTS по схеме TASK-011); семантический поиск — TASK-053, здесь не дублируется.
- Все операции — от имени Owner из контекста TASK-002; мультитенантности и ролей нет.

## Вне рамок

- Семантический поиск и память (TASK-053), планировщик Quartz и доставка напоминаний в каналы (TASK-045, TASK-060/TASK-061/TASK-062), авторизация Owner (TASK-073), миграции схемы (TASK-011), UI-формы (TASK-061).

## Зависимости

- TASK-002
- TASK-011

## Контракты и интерфейсы

- Навыки реализуют `ISkill` из TASK-002; доступ к данным — только через интерфейсы репозиториев (`INoteRepository`, `IFinanceRepository`, `IReminderRepository`, `IContactRepository` или эквивалент из TASK-002/TASK-013), SQL в навыках нет.
- `reminders.create` возвращает `ReminderId` и, при заданном расписании, регистрирует задачу через интерфейс планировщика TASK-002 (фейк в тестах); срабатывание приходит обратно как триггер, доставку делает цепочка.
- Денежные суммы — `decimal`, валюта — ISO-код строкой; отчёт `finance.report` возвращает агрегаты по категориям за период.

## Результаты

- Проект персональных навыков (to-be-created) с четырьмя группами навыков и реестром для роутера/цепочек.
- Unit-тесты на фейковых репозиториях и фейковом планировщике.

## Критерии приёмки

- CRUD заметок и контактов работает на фейковом и реальном (Testcontainers/PostgreSQL) репозитории; удалённая заметка не находится поиском.
- `finance.report` за период сходится с суммой добавленных операций по категориям; операция с суммой <= 0 отклоняется.
- Напоминание с датой в прошлом отклоняется; созданное напоминание видно в `list`, после `cancel` — нет.
- Навыки не содержат SQL и не обращаются к PostgreSQL напрямую (проверка поиском по коду проекта).

## Тестирование

- Уровень: unit + integration. Unit — фейковые репозитории/планировщик; integration — против тестовой PostgreSQL (схема TASK-011) для репозиторных сценариев. Роутер и каналы заменяются моками.
