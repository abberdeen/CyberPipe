# 03-service-host — Хост службы, управление и изоляция

## Назначение

Область отвечает за то, как CyberPipe живёт на машине владельца:

```text
Windows Service (Service, Program Files)  <-управление->  Desktop (Avalonia)
        |
        +-- Brainstem: изолированный воркер (тяжёлые/рискованные задачи)
        +-- Sandbox: Restricted Token + Job Object + Deny-ACL
```

Ключевые решения: `docs/plans/DECISIONS.md` (Q24, Q13) и `docs/plans/initial_arch/17-adr-mvp.md` (ADR-006, ADR-008) имеют приоритет над старым текстом планов. Service и Desktop — два отдельных процесса. Service работает постоянно и без UI. Desktop только управляет Service и показывает состояние. Моделей внутри хоста нет. Guest нет, только Owner.

Платформа: .NET 10, Avalonia для всех ОС, ручной фокус тестирования — Windows. Пути проектов ниже помечены «к созданию»: кода ещё нет, `CyberPipe.slnx` пуст.

## Задачи

| ID | Задача | Результат |
|---|---|---|
| TASK-020 | Windows Service Host | Служба ставится в Program Files, стартует без UI, отвечает на health-check |
| TASK-021 | Управление Service из Desktop | Start/Stop/Restart и статус из Desktop без прямого доступа Desktop к данным |
| TASK-022 | Супервизор Brainstem-воркера | Изолированный воркер: старт, heartbeat, перезапуск, остановка |
| TASK-023 | Sandbox: Restricted Token + Job Object + Deny-ACL | Запуск процесса с урезанными правами и настраиваемым лимитом памяти |

## Порядок выполнения

1. TASK-023 — без зависимости от хоста, только контракты TASK-002.
2. TASK-020 — фундамент хоста.
3. TASK-022 — после TASK-020 и TASK-023.
4. TASK-021 — после TASK-020, поверхность управления для TASK-061.

## Общие правила области

- Зависимости только на TASK-002 (контракты), при необходимости TASK-010/TASK-011 (данные) и TASK-020 (хост). Циклов нет.
- Messaging — только через интерфейсы TASK-002 (заменяемый транспорт, фиксированного брокера нет). Quartz.NET живёт в TASK-045 и здесь не дублируется.
- SLO-числа — целевые ориентиры, а не ворота приёмки.
- Лимит памяти песочницы настраивается (TASK-023), значение по умолчанию задаёт конфигурация TASK-003.
- Все задачи: Статус `Planned`. `Ready` не выставляется, пока есть незакрытые зависимости.
