# TASK-080 — Каталоги моделей в JSON (15 локальных + 8 облачных)

## Цель

Поставить курируемые каталоги моделей CyberPipe как версионируемые JSON-файлы — ровно 15 локальных и ровно 8 облачных моделей — вместе с их загрузчиком, валидатором схемы и проекцией в контрактный тип `ModelDescriptorDto` (TASK-002), чтобы остальные подсистемы выбирали модели по данным, а не по зашитым в код спискам.

## Контекст

- Канон: [DECISIONS.md](../../plans/DECISIONS.md) (Q15, Q16) и [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md) (ADR-007): в приложение ничего не встроено, включая эмбеддинг; жёсткие каталоги 15 локальных + 8 облачных сохранить, вести в виде JSON.
- Исходные списки моделей и поля записи каталога: [13-model-advisor-and-tier-configuration.md](../../plans/initial_arch/13-model-advisor-and-tier-configuration.md) (раздел 3 — 15 локальных; раздел 4 — облачные). В документе 13 облачных кандидатов больше восьми; в канонический каталог входят ровно 8 (см. «Объём работ», п. 3), остальные остаются кандидатами на будущую правку JSON.
- Приложение не связано с конкретными моделями: каталог — стартовый курируемый набор. Пользователь может ввести произвольную модель вручную (Endpoint / ModelId / ApiKey) вне каталога; такая ручная запись каталогом не является и здесь не описывается.
- Стандартный эмбеддинг Tier 1 — `multilingual-e5-small` (Q10, вариант А): не встроен, предлагается при первой установке (мастер TASK-063, установка TASK-081). Его дескриптор описывается отдельным JSON вне счёта «15 + 8» (п. 4), чтобы пороги Tier 1 (TASK-031) и размерность векторов pgvector (TASK-012) брали параметры из данных.
- Признак локальная/облачная (`ModelHostingType`: `Local` / `RemoteCloud`) критичен для TokenBudgetGovernor (TASK-033): локальные стоят $0.00, облачные учитываются в дневном капе $0.50 (Q23). Каталог поставляет признак и цены; сам бюджет здесь не считается.

## Объём работ

1. JSON-файлы каталогов (to-be-created, например `src/CyberPipe.Models/Catalogs/`):
   - `local-models.json` — ровно 15 записей локальных моделей;
   - `cloud-models.json` — ровно 8 записей облачных моделей;
   - `embedding-models.json` — дескриптор стандартного эмбеддинга `multilingual-e5-small` (ONNX, мультиязычный RU/EN) и поле для альтернатив; в счёт «15 + 8» не входит.
   Каждый файл содержит `catalogVersion` (строка версии каталога) и `models` (массив записей).
2. Схема записи модели (единая для local/cloud, сериализуется в `ModelDescriptorDto` из TASK-002): `id` (стабильный строковый идентификатор), `name`, `hostingType` (`Local`|`RemoteCloud`), `recommendedFor` (`LightFastTier2`|`HeavyReasoningTier3`; для эмбеддинга — `EmbeddingTier1`), `provider` (для локальных — рантайм, например `Ollama`; для облачных — провайдер API), `modelId` (идентификатор у провайдера/в рантайме, например тег Ollama), `paramsSummary`, `contextWindowTokens`, `defaultContextTokens` (безопасное окно при запуске, по умолчанию 8192), `q4SizeGb` и `minRamGb` (только для `Local`; для `RemoteCloud` — `null`), `inputPricePer1mUsd` и `outputPricePer1mUsd` (только для `RemoteCloud`; для `Local` — `null`/0), `licenseOrPricing`, `bestFor`.
3. Состав каталогов зафиксировать по документу 13:
   - Локальные (15): Qwen3-8B, Gemma 3n E2B, Llama 3.1 8B Instruct, Phi-4 Mini, Mistral 7B, SmolLM3-3B, Qwen3-4B, DeepSeek-R1 Distill (запись с вариантами 1.5B/8B оформляется двумя полями размера внутри одной записи либо уточняется при наполнении — счёт записей при этом остаётся 15), Gemma 3 4B, GLM-4-9B-0414, Qwen3-0.6B, TinyLlama 1.1B, Phi-4 Mini Reasoning, StableLM Zephyr 3B, Qwen3-1.7B. Значения `q4SizeGb`/`minRamGb`/`contextWindowTokens` — из таблицы раздела 3 документа 13.
   - Облачные (8): Gemini 2.5 Flash-Lite, GPT-4o-mini, Claude 3.5 Haiku, DeepSeek-V3 (Fast API) — для Tier 2; Claude 3.7 Sonnet, GPT-4.1, Gemini 2.5 Pro, DeepSeek-R1 (Cloud API) — для Tier 3. Цены — ориентиры из раздела 4 документа 13 с пометкой в `licenseOrPricing`, что цена справочная и сверяется при подключении провайдера.
4. Дескриптор эмбеддинга: `id` = `multilingual-e5-small`, `hostingType` = `Local`, `recommendedFor` = `EmbeddingTier1`, формат ONNX, размерность вектора и нормализация — явными полями (значения сверяются с паспортом модели при наполнении; размерность не зашивается в код потребителей).
5. Загрузчик каталогов (to-be-created, например `IModelCatalog` в проекте моделей): читает три JSON при старте, отдаёт `IReadOnlyList<ModelDescriptorDto>` по виду каталога, поиск по `id`, фильтрацию по `recommendedFor` и `hostingType`. Чтение — только из поставляемых с приложением файлов; записи в каталоги из приложения нет.
6. Валидатор каталогов: проверка при загрузке и отдельным тестом — ровно 15/8 записей, уникальность `id`, обязательные поля по виду `hostingType` (у `Local` есть `q4SizeGb`/`minRamGb` и нет цен; у `RemoteCloud` есть цены и нет `q4SizeGb`), `defaultContextTokens <= contextWindowTokens`, положительность размеров и цен. Невалидный каталог — явная ошибка загрузки с указанием файла и записи, а не молчаливый пропуск записи.
7. Назначение моделей по ярусам каталог не хранит: тип `TierModelAssignment` определён в TASK-002, выбор пользователя сохраняется областью данных; каталог лишь отдаёт кандидатов для Tier 2 / Tier 3 / Tier 1 (эмбеддинг).

## Контракты и интерфейсы

- Потребляет из TASK-002: `ModelDescriptorDto` (локальная/облачная, провайдер, контекст, цена), признак `ModelHostingType` (`Local`/`RemoteCloud`), категорию `ModelTaskCategory` (`LightFastTier2`/`HeavyReasoningTier3`; значение эмбеддинга Tier 1 — в рамках того же перечисления контрактов), `TierModelAssignment` как тип потребителя.
- Поставляет потребителям: `IModelCatalog` с методами получения локального/облачного/эмбеддинг-каталогов, поиска по `id` и фильтрации по категории и `hostingType`; результат — только DTO из TASK-002, типы JSON-схемы наружу не выходят.
- Файлы `local-models.json`, `cloud-models.json`, `embedding-models.json` и поле `catalogVersion` в каждом — стабильный формат данных; смена формата — только с повышением `catalogVersion` и правкой валидатора.

## Результаты

- Три JSON-каталога (to-be-created): ровно 15 локальных, ровно 8 облачных моделей и дескриптор `multilingual-e5-small`, с заполненными полями по документу 13.
- Загрузчик `IModelCatalog` и валидатор каталогов (to-be-created): битый или неполный каталог отклоняется при загрузке с понятной ошибкой.
- Потребители (TASK-081, TASK-082, TASK-031, TASK-032, TASK-033, TASK-063) получают кандидатов моделей только через `IModelCatalog`, без чтения JSON напрямую.

## Критерии приёмки

- Подсчёт записей программно подтверждён: `local-models.json` — 15, `cloud-models.json` — 8; все `id` уникальны внутри и между каталогами.
- Валидатор отклоняет каталог с: дублем `id`, локальной моделью без `q4SizeGb`/`minRamGb`, облачной моделью без цен, `defaultContextTokens > contextWindowTokens`. Каждое отклонение содержит имя файла и `id` записи.
- Каждая локальная запись имеет `recommendedFor` Tier 2 или Tier 3; в облачном каталоге есть записи обеих категорий (Tier 2 и Tier 3).
- `embedding-models.json` содержит `multilingual-e5-small` с явной размерностью вектора; загрузчик отдаёт его по запросу эмбеддинг-каталога.
- В коде загрузчика нет зашитого списка моделей: удаление записи из JSON (в тестовой копии каталога) меняет результат `IModelCatalog` без перекомпиляции логики.
- Поиск по коду области не находит цен облачных моделей и размеров локальных моделей вне JSON-файлов каталогов.

## Тестирование

- Уровень: unit + contract.
- Как: unit — валидатор и загрузчик на тестовых копиях JSON (валидный каталог, дубли, пропущенные поля, неверные счётчики 14/16 и 7/9); contract — round-trip сериализации каждой записи каталога в `ModelDescriptorDto` и обратно без потери полей, проверка ровно 15/8 на поставляемых файлах. Реальные провайдеры и рантаймы не вызываются; потребители тестируются на фейковом `IModelCatalog`.
