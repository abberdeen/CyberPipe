# TASK-082 — Советник по железу и совместимости локальных моделей

## Цель

Реализовать связку из двух сервисов: пробу железа ПК (`IHardwareCapabilitiesProbe` — RAM, CPU, GPU/VRAM, диск) и советника совместимости (`IModelCompatibilityAdvisor`), который для каждой локальной модели каталога TASK-080 рассчитывает потребность в памяти с учётом KV-Cache и выдаёт вердикт «оптимально / совместимо / недостаточно ресурсов» с человекочитаемым объяснением для UI.

## Контекст

- Канон и исходная логика: [13-model-advisor-and-tier-configuration.md](../../plans/initial_arch/13-model-advisor-and-tier-configuration.md) (раздел 2): два сервиса, DTO `HostHardwareProfile`, `HardwareFitVerdict`, формула требуемой памяти `RequiredMemoryGb = Q4SizeGb * 1.35 + 1.0` (веса Q4 + KV-Cache при окне по умолчанию 8192 токенов + буферы рантайма). При расхождении документа 13 с [DECISIONS.md](../../plans/DECISIONS.md) и [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md) верны DECISIONS.md и ADR-007.
- Советник нужен, чтобы новичок не повесил систему моделью, не влезающей в RAM/VRAM (Q15: инструмент выбора локальных моделей в UI — TASK-081 показывает вердикты, экран моделей Desktop TASK-061 их отображает). Вердикт — подсказка, а не запрет: жёсткой блокировки установки здесь нет (подтверждение при риске — TASK-081).
- Оцениваются только локальные модели (`hostingType = Local`, 15 записей TASK-080). Облачные модели железа не требуют: для них советник лишь отдаёт список из каталога для экрана выбора (без вердиктов).
- Платформы: один проект под все ОС (Q6), фокус ручного тестирования — Windows. На ОС/конфигурациях, где характеристику снять нельзя (нет GPU, недоступен AVX2, виртуальная машина), проба обязана возвращать профиль с неизвестными полями, а не падать; советник трактует неизвестное консервативно (см. критерии приёмки).
- Коэффициенты формулы (1.35 и 1.0 ГБ) и пороги вердиктов — не ворота приёмки, а стартовые эвристики: выносятся в конфигурацию (TASK-003) с указанными значениями по умолчанию, чтобы калибровать по замерам без правки кода.

## Объём работ

1. Реализация `IHardwareCapabilitiesProbe` (контракт — TASK-002; to-be-created, проект телеметрии/хоста): асинхронный снимок `HostHardwareProfile`:
   - `TotalRamGb`, `AvailableRamGb` — общая и свободная RAM хоста;
   - `CpuLogicalCores`, `SupportsAvx2` — логические ядра и поддержка AVX2 (на не-x86 архитектурах — `null`/неизвестно, а не `false`-ошибка);
   - `GpuModelName`, `DedicatedVramGb` — дискретная/интегрированная GPU и объём VRAM; при отсутствии GPU — `null`/0;
   - `FreeDiskSpaceGb` — свободное место на диске каталога данных приложения.
   Проба не требует прав администратора, не ходит в сеть, кэшируется на время жизни процесса с явным обновлением по запросу (RAM/диск меняются, CPU/GPU — нет).
2. Реализация `IModelCompatibilityAdvisor` (контракт — TASK-002; to-be-created, проект моделей/оркестрации): для каждой локальной модели каталога TASK-080:
   - `requiredMemoryGb = Round(Q4SizeGb * 1.35 + 1.0, 1)` — коэффициенты из конфигурации;
   - вердикт по правилам документа 13: `InsufficientResources`, если `TotalRamGb < MinRamGb` или `AvailableRamGb < requiredMemoryGb`; `Optimal`, если `DedicatedVramGb >= requiredMemoryGb` или (`TotalRamGb >= MinRamGb * 1.5` и `AvailableRamGb >= requiredMemoryGb * 1.4`); иначе `Compatible`;
   - `UserFriendlyExplanation` — строка для UI вида «нужно ~{requiredMemoryGb} ГБ с учётом KV-Cache (окно 8K), свободно {AvailableRamGb} ГБ RAM» плюс причина вердикта; без жаргона и без эмодзи-обязательности (иконка — забота UI);
   - сортировка результата: `Optimal` -> `Compatible` -> `InsufficientResources`, внутри группы — по возрастанию `requiredMemoryGb`; фильтр по категории `LightFastTier2`/`HeavyReasoningTier3` (параметр запроса);
   - отдельный метод отдаёт облачные модели каталога (8 записей) с фильтром по категории, без вердиктов и без пробы железа.
3. Консервативная трактовка неизвестных: если `AvailableRamGb` неизвестна — вердикт не выше `Compatible` и в объяснение добавляется «не удалось определить свободную память»; если неизвестна `TotalRamGb` — модель не получает `Optimal`. Проба, упавшая целиком, даёт советнику пустой профиль, и все вердикты — не выше `Compatible` с пометкой о недоступности данных железа.
4. Интеграция по контрактам (не реализация потребителей): советник отдаёт `ModelCompatibilityReport`/`ModelCompatibilityEvaluation` (типы TASK-002) потребителям TASK-081 и TASK-061; экран «Паспорт ПК» («Ваш ПК: 32 ГБ RAM (свободно 18.4 ГБ) | CPU: 16 потоков (AVX2) | GPU: RTX 4070 (12 ГБ VRAM)») собирается UI из `HostHardwareProfile`, здесь делается только его снимок и форматируемые числовые поля.

## Вне рамок

- Каталоги моделей и значения `Q4SizeGb`/`MinRamGb` (TASK-080); установка моделей и рантайма (TASK-081).
- Мониторинг ресурсов во время работы моделей (контроль RAM/VRAM перед вызовом LLM, `ISystemResourceMonitor` из документа 13) — это рантайм-контроль роутеров, а не советник выбора; здесь только разовый снимок для выбора модели.
- Бенчмарки скорости генерации, замер реальной скорости токен/с и автоподбор модели без участия пользователя.
- Назначение моделей на ярусы и бюджет (TASK-032, TASK-033, TASK-061): советник не пишет `TierModelAssignment`.
- Поддержка серверного/многопользовательского железа: только локальный ПК владельца (только Owner, Q18).

- Поставляет потребителям TASK-081/TASK-061: асинхронную оценку всех локальных моделей (с необязательным фильтром по категории) и снимок профиля железа. Коэффициенты формулы и пороги — конфигурация TASK-003 со значениями по умолчанию 1.35, 1.0 ГБ, множители 1.5/1.4.

## Результаты

- Реализация пробы железа (to-be-created): снимок `HostHardwareProfile` на Windows без прав администратора и без сети; на прочих ОС — деградация в неизвестные поля без исключений.
- Реализация советника (to-be-created): отсортированный список оценок всех 15 локальных моделей с вердиктами и объяснениями; облачный список (8) без вердиктов.
- UI установщика (TASK-081) и экран моделей (TASK-061) могут показать «Паспорт ПК» и вердикт у каждой локальной модели, не зная формулы.

## Критерии приёмки

- Формула: для модели с `Q4SizeGb = 5.2` требуемая память — `Round(5.2 * 1.35 + 1.0, 1) = 8.0` ГБ; расчёт подтверждён модульным тестом на границах всех трёх вердиктов.
- Вердикты на синтетических профилях: (а) `TotalRamGb < MinRamGb` -> `InsufficientResources`; (б) VRAM покрывает требуемую память -> `Optimal`; (в) RAM покрывает с запасом 1.5/1.4 -> `Optimal`; (г) памяти впритык -> `Compatible`. Каждое объяснение содержит требуемый и доступный объёмы.
- Сортировка: все `Optimal` раньше `Compatible`, те раньше `InsufficientResources`; фильтр по Tier 2 оставляет только `LightFastTier2`, по Tier 3 — только `HeavyReasoningTier3`.
- Неизвестные поля: профиль без `AvailableRamGb` — ни одна модель не получает `Optimal`; полностью пустой профиль — все вердикты не выше `Compatible` с пометкой о недоступности данных.
- Проба на реальной Windows-машине возвращает положительные RAM/ядра/диск и не бросает исключений при отсутствии дискретной GPU.
- Облачный метод возвращает ровно записи облачного каталога (8) и не вызывает пробу железа.

## Тестирование

- Уровень: unit (+ ручная интеграционная проверка пробы на Windows).
- Как: unit — советник на фейковом `IModelCatalog` (TASK-080) и фейковой пробе с таблицей синтетических профилей (границы вердиктов, неизвестные поля, пустой профиль, обе категории); проба — unit на абстракции источника системных метрик (фейковые значения ОС) плюс ручной smoke на Windows: снимок сверяется с диспетчером задач/`systeminfo`. Реальное железо в автотесты не требуется; потребители используют фейк советника.
