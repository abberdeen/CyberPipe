# 07-channels-ui — Каналы и пользовательские интерфейсы

## Назначение области

Каналы ввода/вывода и интерфейсы владельца CyberPipe (.NET 10): Telegram — первый канал, Avalonia Desktop и CLI развиваются параллельно с ним (Q19). Все три работают только через контракты TASK-002 и собственные абстракции сообщений с заменяемым транспортом; фиксированного брокера нет. Только Owner, роли Guest нет.

Канон: [DECISIONS.md](../../plans/DECISIONS.md) (Q4, Q6, Q18, Q19, Q24) и [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md). Старые тексты про Guest, фиксированный брокер и «Telegram только для MVP» не действуют.

## Общие принципы

- Цепочки только `Trigger -> Skill -> Script -> Delivery` (триггеры: Webhook, Cron, function call, chat). Визуального редактора нет; каналы лишь создают chat-триггеры и доставляют результаты Delivery.
- Service (Windows-служба, `Program Files`) и Desktop — раздельные процессы; Desktop управляет Service (старт/стоп/перезапуск) через контракт TASK-021, CLI — через тот же контракт. Закрытие Desktop/CLI службу не останавливает.
- HITL-подтверждения приходят в Telegram и Avalonia (механизм — TASK-046); каналы только рендерят запрос и возвращают решение Owner.
- Модели не встроены: при первом запуске мастер (TASK-063) предлагает стандартный мультиязычный эмбеддинг `multilingual-e5-small` для Tier 1; установка/настройка локальных моделей (например Qwen3 через Ollama) — UI-инструмент TASK-081, каталоги 15 локальных + 8 облачных JSON — TASK-080. Каналы моделей не устанавливают.
- Одна PostgreSQL + pgvector; Quartz.NET в той же PostgreSQL (расписания Cron — TASK-045, просмотр в UI — TASK-061 как потребитель).
- Токен-бюджет по умолчанию: $0.50/день, 4000/12000 токенов, 3 облачных / 5 локальных ходов, всё конфигурируемо (применение — TASK-033); каналы только показывают статус бюджета из контрактов.
- Код пока отсутствует (`CyberPipe.slnx` пуст); пути проектов помечены «to-be-created», команды `dotnet build/test` — плановые стандартные команды .NET 10.
