# TASK-061 — Avalonia Desktop UI

## Цель

Дать владельцу настольный интерфейс CyberPipe на Avalonia (все ОС, ручной фокус — Windows): чат с ассистентом, просмотр цепочек и их запусков, HITL-подтверждения, управление службой Service и просмотр расписаний — без визуального редактора цепочек.

## Контекст

- Один проект Avalonia под все ОС (Q6); Service и Desktop — раздельные вещи (Q24): Desktop можно закрывать, Service продолжает работу и может слать нотификации через каналы.
- Desktop управляет Service (запуск/остановка/перезапуск) не сам, а через контракт управления службой TASK-021; здесь только UI поверх него.
- Визуального редактора цепочек нет и не будет (Q5): цепочки `Trigger -> Skill -> Script -> Delivery` только просматриваются и запускаются вручную (function call), определение цепочек — файлы конфигурации TASK-040.
- Встроенного дашборда Quartz.NET нет (Q7): просмотр расписаний делается в этом UI как потребителе контрактов, сам планировщик — TASK-045.
- Первый запуск ведёт в мастер TASK-063; эта задача лишь открывает его при признаке «не настроено» и не реализует шаги мастера.

## Объём работ

1. Проект Desktop (to-be-created, например `src/CyberPipe.Desktop/`): Avalonia-приложение .NET 10, MVVM, темы светлая/тёмная, локализация RU/EN как минимум для оболочек (строки — ресурсы, не хардкод в View).
2. Экран чата: история диалога из контрактов TASK-002, ввод текста и вложений, индикация яруса обработки и статуса бюджета (данные — DTO TASK-033, показ без собственной логики лимитов), кнопка прерывания текущей задачи.
3. Экран цепочек: список цепочек (определения TASK-040, только чтение), список запусков и их шагов с контрольными точками (данные TASK-044 через контракты), ручной запуск function call, просмотр результата Delivery. Редактирования определения в UI нет.
4. Экран HITL: очередь запросов подтверждений из TASK-046 — «Одобрить / Отклонить / Изменить», с контекстом действия; решение уходит через контракт TASK-046.
5. Панель Service: статус службы, кнопки Start/Stop/Restart через `IServiceControl` (TASK-021), понятное состояние «служба недоступна» вместо зависания, версия сборки Service и Desktop.
6. Экран расписаний: список Cron-заданий Quartz (чтение через контракты TASK-045), включение/отключение задания, если контракт это позволяет; создание/правка cron-выражений — только текстовым полем с валидацией из контракта, без конструктора расписаний.
7. Экран моделей — точка входа, а не реализация: переход к инструменту установки локальных моделей TASK-081 и показ текущих назначений моделей по ярусам из каталогов TASK-080 (чтение DTO); установка моделей здесь не делается.
8. Уведомления Desktop: системные нотификации о завершённых запусках и HITL-запросах, когда окно свёрнуто; клик открывает соответствующий экран.

## Вне рамок

- Управление службой как механизм (TASK-021), хост службы (TASK-020), мастер первого запуска (TASK-063).
- Редактирование цепочек, cron-конструктор, визуальный редактор любого вида.
- Установка/настройка моделей и Ollama (TASK-081), каталоги моделей (TASK-080), советник по железу (TASK-082).
- Реализация роутера, цепочек, HITL, планировщика — UI только потребитель их контрактов.

## Контракты и интерфейсы

- Потребляет из TASK-002: DTO сообщений канала (`ChannelKind.Desktop`), HITL-запроса/решения, статуса бюджета, цепочек и запусков, `Result<T>` для вызовов Service.
- Управление службой — только `IServiceControl` из TASK-021 (Start/Stop/Restart/Status); прямых вызовов Windows Service Control Manager из UI нет.
- ViewModel не ссылаются на транспортные типы и драйверы PostgreSQL; все данные — через интерфейсы контрактов, подменяемые фейками в тестах.

## Результаты

- Проект Avalonia Desktop (to-be-created) с экранами: чат, цепочки, HITL, Service, расписания, вход в модели и мастер.
- Приложение стартует при остановленной службе и честно показывает её недоступность; при запущенной — полный цикл чата на фейковом бэкенде.

## Критерии приёмки

- Чат: сообщение уходит фейковому роутеру, ответ и статус бюджета отображаются; прерывание задачи доступно во время выполнения.
- Панель Service: кнопки вызывают Start/Stop/Restart фейкового `IServiceControl`, статус обновляется без перезапуска Desktop; при недоступной службе UI не зависает и показывает состояние.
- HITL: запрос из фейкового TASK-046 появляется в очереди, решения «Одобрить/Отклонить/Изменить» уходят обратно с тем же идентификатором запроса.
- Цепочки: список и шаги запуска отображаются из фейковых данных; кнопки «редактировать цепочку» в UI нет.
- Расписания: список Cron-заданий отображается; некорректное cron-выражение отклоняется валидацией контракта с понятным сообщением.
- Закрытие Desktop не вызывает Stop службы.

## Тестирование

- Уровень: unit + component.
- Как: unit — ViewModel на фейках `IServiceControl`, роутера, HITL и расписаний (Avalonia.Headless для тестов ViewModel/навигации); component — Desktop целиком на полном наборе фейков контрактов TASK-002 без реальной службы и БД. Ручная проверка на Windows (и smoke на второй ОС) — по чек-листу приёмки.
