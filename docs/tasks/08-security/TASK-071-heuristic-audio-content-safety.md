# TASK-071 — Эвристическая безопасность аудио и контента

## Цель

Оценивать риск воспроизведения аудио/медиа для владельца по эвристикам и семантической близости контента к рисковым категориям и возвращать соразмерное действие (разрешить, снизить громкость пропорционально риску, предупредить, отложить/запретить), а не применять фиксированное ограничение громкости.

## Контекст

- Решение Q17 (DECISIONS.md) прямо отменяет фиксированный Volume Clamp (60%/25%): вместо него — эвристическая оценка риска по содержанию/аудио, времени суток, длительности и уровню сигнала; снижение громкости допустимо только как следствие оценки риска.
- CyberPipe — локальный ассистент одного Owner; воспроизведение выполняют host-навыки медиа (TASK-050), оценка риска — отдельная проверка до воспроизведения, вызываемая через контракты TASK-002.
- Семантическая часть переиспользует эмбеддинги Tier 1: стандартная мультиязычная модель `multilingual-e5-small` предлагается при первом запуске (TASK-063), модели в приложение не встроены; провайдер эмбеддингов приходит через абстракцию TASK-002.
- Категории риска описываются прототипами (текстовые описания/примеры) в конфигурации, а не зашитым списком ключевых слов: классификация — по смыслу, включая синонимы и длинные формулировки на RU/EN.
- Код отсутствует (`CyberPipe.slnx` пуст); проекты помечены как «к созданию».

## Объём работ

- Создать в проекте безопасности (к созданию: `src/CyberPipe.Security/`) сервис оценки риска воспроизведения по контрактам TASK-002.
- Входные сигналы эвристики (каждый — опциональный, отсутствие сигнала не блокирует остальные):
  - семантика: близость эмбеддинга названия/описания/транскрипта контента к прототипам рисковых категорий (резкие/пугающие звуки, крики, тревожный контент, явно громкие события) через провайдер эмбеддингов TASK-002;
  - сигнал: пиковый уровень и интегральная громкость (LUFS/peak), если вызывающий передал измеренные метаданные аудио; резкий перепад уровня на старте;
  - контекст: локальное время Owner (ночной интервал из конфигурации), длительность контента, источник (канал/цепочка), флаг «внезапное воспроизведение без явного запроса Owner».
- Агрегация: взвешенная оценка риска `0..1` с конфигурируемыми весами и порогами; каждый вклад фиксируется в объяснении решения (какой сигнал и насколько повлиял).
- Действия по порогам (все пороги — конфигурация TASK-003): `Allow`, `ReduceVolume` (целевой уровень вычисляется из оценки риска, а не фиксированной константой вида 60%/25%), `Warn` (воспроизведение только после подтверждения вызывающей стороной/HITL TASK-046), `DeferOrDeny` (ночной внезапный громкий контент по жёсткой политике конфигурации).
- Прототипы категорий: загрузка из конфигурации/JSON, вычисление их эмбеддингов один раз при старте, кэш в памяти; обновление прототипов без изменения кода.
- Деградация: при недоступности провайдера эмбеддингов семантический сигнал помечается отсутствующим, решение строится по сигнальным/контекстным эвристикам; при отсутствии всех сигналов — `Warn`, а не безусловный `Allow` (fail-cautious для внезапного воспроизведения) — поведение фиксируется конфигурацией.
- Журналирование решений и вкладов сигналов (без содержимого аудио/транскриптов) через TASK-004.

## Вне рамок

- Само воспроизведение, управление громкостью ОС и медиа-навыки — TASK-050; задача только возвращает рекомендуемое действие и целевой уровень.
- Фиксированный Volume Clamp как универсальное ограничение — прямо исключён решением Q17 и не реализуется даже как fallback.
- Транскрибация аудио (Whisper) — TASK-052; здесь транскрипт принимается готовым текстом от вызывающего, если он есть.
- Установка/настройка моделей и ONNX-инференс Tier 1 как инфраструктура — TASK-031/TASK-063/TASK-081; здесь только потребление провайдера эмбеддингов по контракту.
- HITL-рендеринг предупреждений — TASK-046/TASK-060/TASK-061; здесь только действие `Warn`.

## Контракты и интерфейсы

Используются абстракции из TASK-002 (точные имена — по факту TASK-002, ниже — требуемая семантика):

- `IAudioContentSafetyEvaluator`:
  - `Task<AudioSafetyDecision> EvaluateAsync(AudioSafetyRequest request, CancellationToken ct)`.
- `AudioSafetyRequest`: заголовок/описание контента, транскрипт (опционально), метаданные сигнала (`PeakDbfs`, `LoudnessLufs`, `StartTransientDb` — опционально), длительность, локальное время Owner, источник, флаг явного запроса Owner на воспроизведение.
- `AudioSafetyDecision`: действие (`Allow` / `ReduceVolume` / `Warn` / `DeferOrDeny`), оценка риска `0..1`, рекомендуемый целевой уровень громкости `0..1` (только для `ReduceVolume`, вычислен из риска), объяснение: список вкладов (`SignalContribution`: вид сигнала, значение, вес, вклад).
- Провайдер эмбеддингов из TASK-002: `Task<ReadOnlyMemory<float>> EmbedAsync(string text, CancellationToken ct)` — семантика Tier 1, модель `multilingual-e5-small` по умолчанию конфигурации.
- Прототипы категорий и веса/пороги — конфигурация TASK-003 (JSON допустим); интерфейс evaluator от формата хранения не зависит.

## Результаты

- Реализация `IAudioContentSafetyEvaluator` в проекте безопасности (к созданию).
- Стартовый набор прототипов рисковых категорий (RU/EN) и весов/порогов в конфигурации по умолчанию; фиксированных 60%/25% в конфигурации и коде нет.
- Unit-тесты агрегации риска, пропорционального снижения громкости и деградации без эмбеддингов.

## Критерии приёмки

- Контент с высокой семантической близостью к рисковой категории и высоким пиковым уровнем ночью получает более строгое действие, чем тот же контент днём по явному запросу Owner (монотонность по риску в табличном тесте).
- Для `ReduceVolume` целевой уровень монотонно убывает с ростом оценки риска и не равен одной фиксированной константе для разных рисков; поиск по коду/конфигурации не находит универсального clamp 60%/25%.
- Длинное/синонимичное описание рисковой категории (не совпадающее дословно с прототипом) классифицируется по близости эмбеддингов фейкового провайдера, а не по ключевым словам.
- При недоступном провайдере эмбеддингов решение принимается по сигналу/контексту, отсутствие семантики отражено в объяснении; при отсутствии всех сигналов для внезапного воспроизведения возвращается `Warn`.
- Объяснение решения содержит вклад каждого использованного сигнала; в журнал не попадают транскрипт и содержимое контента.
- Пороги, веса, ночной интервал и прототипы меняются только конфигурацией, без изменения кода (тест с альтернативной конфигурацией).

## Тестирование

- Уровень: unit.
- Как: фейковый провайдер эмбеддингов с заданными векторами (близкие/далёкие прототипы, RU/EN синонимы), фейковые часы (`TimeProvider`) для ночного интервала, табличные тесты «сигналы → действие/уровень», тест монотонности целевого уровня, тест деградации при бросающем исключение провайдере. Реальная ONNX-модель, аудио-файлы и PostgreSQL не требуются.
