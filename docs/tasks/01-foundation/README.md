# 01-foundation — Фундамент решения

## Назначение

Базовый слой CyberPipe (.NET 10): каркас решения, общие контракты, конфигурация и секреты, логирование и диагностика. Все остальные области зависят от этого слоя только через контракты (`CyberPipe.Contracts`), без обратных зависимостей.

Канонические решения: [DECISIONS.md](../../plans/DECISIONS.md) и [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md). При расхождении со старыми текстами планов верны эти два документа.

Ключевые ограничения области:

- Одна база PostgreSQL + pgvector; Quartz.NET — в той же PostgreSQL (детали — область `02-data`, здесь только контракты и конфигурация).
- Обмен сообщениями — только через собственные интерфейсы проекта, транспорт заменяем и не фиксируется.
- Цепочки — только `Trigger -> Skill -> Script -> Delivery`; визуального редактора нет.
- Роли Guest нет: только Owner.
- DevTools/Git/Build-навыки удалены из продукта.
- Модели не встроены в приложение; каталоги и установка — область `09-models`, здесь только конфигурационные контракты.

## Общие правила для области

- `CyberPipe.Contracts` не зависит ни от одного другого проекта решения.
- Никаких ссылок на конкретный брокер сообщений, SQLite, Hangfire в коде и конфигурации фундамента.
- Пути проектов помечены как «к созданию» (to-be-created), пока задача TASK-001 не выполнена: кода в решении ещё нет, `CyberPipe.slnx` пуст.
- Команды проверки — стандартные команды .NET (`dotnet build`, `dotnet test`); имена тестовых проектов уточняются в TASK-001.
