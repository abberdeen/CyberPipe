# TASK-003 — Конфигурация и секреты

## Цель

Дать решению единый механизм конфигурации (файл + переменные окружения + переопределения из UI) и хранения секретов (платформенное хранилище ОС), с дефолтами из решений владельца и без секретов в открытом виде на диске и в логах.

## Контекст

- Канон: [DECISIONS.md](../../plans/DECISIONS.md), [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md) (ADR-001, ADR-007, ADR-008).
- Всё хранится в одной PostgreSQL + pgvector; если подключиться к БД не удалось — приложение просит пользователя восстановить подключение и спрашивает пароль от БД (механизм подключения — TASK-010; здесь — только конфигурация строки подключения и секрета пароля).
- Дефолты бюджета (Q23, всё настраиваемо): дневной кап $0.50, soft 4000 / hard 12000 токенов на задачу, 3 облачных / 5 локальных ходов.
- Модели не встроены: при первом запуске предлагается стандартная мультиязычная эмбеддинг-модель `multilingual-e5-small` для Tier1 (установка — TASK-063, TASK-081); здесь — только ключи конфигурации выбора моделей по ярусам.
- Лимит памяти песочницы не имеет жёсткого дефолта (Q9) — задаётся настройкой; изоляция: Restricted Token + Job Object + Deny-ACL (реализация — TASK-023).
- SLO-цифры — цели, а не ворота приёмки: в конфигурации они помечаются как `targets`, а не `limits`.
- Роли Guest нет; конфигурация содержит только идентификаторы Owner (белый список — TASK-073).

## Объём работ

1. Классы опций (to-be-created, `src/CyberPipe.Contracts/` или отдельный раздел конфигурации в Contracts по решению TASK-002):
   - `DatabaseOptions` (хост, порт, база, пользователь; пароль — только ссылка на секрет, не значение).
   - `BudgetOptions` (дефолты Q23 выше, все поля переопределяемы).
   - `RouterOptions` (включение ярусов Tier0..Tier3, назначение моделей по ярусам, порог семантического кэша).
   - `ModelOptions` (выбранная эмбеддинг-модель Tier1 по умолчанию `multilingual-e5-small`, каталоги моделей — пути к JSON, сами каталоги — TASK-080).
   - `SandboxOptions` (лимит памяти — nullable, без жёсткого дефолта; таймауты).
   - `ChannelOptions` (Telegram включён, токен бота — только ссылка на секрет; Desktop/CLI без секретов).
   - `OwnerOptions` (идентификаторы Owner для Telegram/Desktop/CLI).
2. Загрузка конфигурации: `appsettings.json` (to-be-created, рядом с Service) -> переменные окружения с префиксом `CYBERPIPE_` -> переопределения, сохранённые из UI (файл переопределений в каталоге данных пользователя). Приоритет и правила слияния документируются в коде опций.
3. Абстракция секретов `ISecretStore` (контракт — в `CyberPipe.Contracts`, если не создан в TASK-002 — создать здесь): `Set/Get/Delete` по ключу; реализация по умолчанию — платформенное хранилище (Windows Credential Manager / DPAPI, Linux Secret Service, macOS Keychain). Файловая реализация — только для тестов, с явным признаком небезопасности.
4. Маскирование: тип-обёртка `SecretValue`, чей `ToString()` возвращает `[REDACTED]`; интеграция с логированием — TASK-004, исходящая очистка — TASK-072.
5. Валидация опций при старте: понятные ошибки с именем ключа (без значений секретов), падение старта при невалидной обязательной конфигурации.

## Контракты и интерфейсы

- `ISecretStore` (Set/Get/Delete по строковому ключу, значения — `SecretValue`).
- Классы опций из п. 1 раздела «Объём работ» с дефолтами, совпадающими с Q23/ADR; потребители читают только опции, не файлы напрямую.
- Ключи секретов: `database.password`, `telegram.botToken` (единый реестр имён ключей в одном месте кода).

## Результаты

- Загрузка и валидация конфигурации из трёх источников с документированным приоритетом.
- Реализация `ISecretStore` на платформенном хранилище + тестовая файловая реализация.
- Дефолты бюджета, моделей ярусов и песочницы соответствуют решениям владельца.

## Критерии приёмки

- При пустой конфигурации приложение стартует с дефолтами Q23; переопределение переменной `CYBERPIPE_Budget__DailyCapUsd` меняет дневной кап без пересборки.
- Секрет, записанный через `ISecretStore`, не встречается в открытом виде ни в файлах конфигурации, ни в выводе `ToString()`.
- Невалидная конфигурация (например, отрицательный кап бюджета) останавливает старт с ошибкой, называющей ключ.
- В конфигурации и коде нет ключей, связанных с Guest, DevTools/Git/Build, SQLite и Hangfire.

## Тестирование

- Уровень: unit.
- Как: тесты слияния источников конфигурации (файл < окружение < UI-переопределения), тесты round-trip секретов на тестовой файловой реализации, тесты валидации. Платформенное хранилище тестируется вручную на Windows (фокус ручного тестирования); в CI используется файловая реализация.
