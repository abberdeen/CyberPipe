# TASK-004 — Логирование и диагностика

## Цель

Дать всем процессам (Service, Desktop, CLI, Brainstem) единое структурированное логирование без утечки секретов и команду диагностики состояния, на которую смогут опираться UI, CLI и задачи интеграции.

## Контекст

- Канон: [DECISIONS.md](../../plans/DECISIONS.md), [17-adr-mvp.md](../../plans/initial_arch/17-adr-mvp.md). SLO-цифры — цели («доска почёта»), а не ворота приёмки: диагностика показывает фактические значения рядом с целевыми, но не блокирует работу при их превышении.
- Секреты маскируются обёрткой `SecretValue` из TASK-003; исходящая очистка данных (egress) — TASK-072, здесь маскируются только логи.
- Desktop управляет Service (TASK-021): диагностика должна уметь показать состояние службы, подключения к PostgreSQL и транспорта сообщений, не запуская бизнес-логику.
- Каналы параллельны (Telegram — первый, Avalonia, CLI): в логах каждое событие несёт канал, цепочку и ярус маршрутизации, чтобы сценарии TASK-091/TASK-092 разбирались по логам.

## Объём работ

1. Настройка Serilog (или эквивалента из стандартного стека .NET — выбор фиксируется в коде этой задачи) для всех процессов: структурированные события, уровни через конфигурацию TASK-003 (ключ `Logging`), запись в файл с ротацией по дням и размеру в каталог данных пользователя и в консоль для CLI/Desktop.
2. Обогащение событий: `ProcessName`, `ChannelKind`, `ChainId`/`RunId` (если есть в контексте), `IntentTier`, расход токенов и стоимость для вызовов LLM (поля из DTO TASK-002).
3. Маскирование: форматер/деструктор, заменяющий значения `SecretValue` и известные ключи секретов (`database.password`, `telegram.botToken`) на `[REDACTED]` на любом уровне вложенности.
4. Контракт диагностики `IDiagnosticsService` (в `CyberPipe.Contracts`, если не создан в TASK-002 — создать здесь): `GetHealthAsync()` возвращает `HealthReportDto` — состояние процесса, подключение к PostgreSQL (без строки подключения), транспорт сообщений (тип реализации, без секретов), версия приложения, фактические значения SLO-целей (цели берутся из конфигурации как `targets`).
5. Реализация сбора здоровья: проверки выполняются через интерфейсы TASK-002 (fake-реализации в тестах); реальное подключение к БД подключается в TASK-010 без изменения контракта.
6. Сквозной идентификатор операции: генерация и прокидывание `RunId` через `AsyncLocal`-контекст логера для цепочек и вызовов каналов.

## Вне рамок

- Egress-санитизация исходящих данных в LLM/Telegram (TASK-072); здесь — только логи.
- Метрики, дашборды и алерты; отображение диагностики в UI (TASK-061, TASK-062 — потребители контракта).
- Сборка дампов, трейсинг OpenTelemetry и экспорт вовне приложения.
- Логика управления службой (TASK-021); диагностика только читает состояние.

## Контракты и интерфейсы

- `IDiagnosticsService.GetHealthAsync() -> HealthReportDto` (DTO — из TASK-002 или создаётся здесь в Contracts).
- Единый шаблон структурированного события и обязательные поля из п. 2; потребители (каналы, цепочки, роутер) пишут только через `ILogger<T>` с этими полями.
- Гарантия маскирования: ни одно событие не содержит значений секретов из реестра ключей TASK-003.

## Результаты

- Единая инициализация логирования для Service/Desktop/CLI/Brainstem одной точкой входа.
- `HealthReportDto` и реализация диагностики на fake-зависимостях.
- Маскирование секретов в логах, подтверждённое тестами.

## Критерии приёмки

- Запись события с объектом, содержащим `SecretValue` и поле `telegram.botToken`, даёт в файле лога только `[REDACTED]`.
- `GetHealthAsync()` на fake-реализациях возвращает отчёт со всеми полями и не бросает исключений при недоступной БД (состояние `Degraded` с причиной без секретов).
- Событие, записанное внутри контекста `RunId`, содержит этот `RunId` в файле лога.
- Уровень логирования меняется конфигурацией TASK-003 без пересборки.

## Тестирование

- Уровень: unit + component.
- Как: unit-тесты маскирования и обогащения на in-memory приёмнике событий; component-тест диагностики на fake-реализациях `IMessageTransport` и проверки БД. Ручная проверка на Windows: запуск CLI-заглушки, просмотр файла лога.
