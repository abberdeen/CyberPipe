# TASK-030 — Tier 0: regex-роутер

## Цель

Мгновенно и без внешних вызовов распознавать типовые команды и запросы по регулярным выражениям, отдавая результат с уверенностью либо эскалируя запрос на Tier 1.

## Контекст

- CyberPipe — локальный персональный ассистент (.NET 10), один PostgreSQL + pgvector, цепочки только `Trigger -> Skill -> Script -> Delivery`.
- Маршрутизация четырёхъярусная: Tier 0 regex → Tier 1 ONNX-эмбеддинги + семантический кэш → Tier 2 лёгкая LLM → Tier 3 тяжёлая LLM.
- Tier 0 — самый дешёвый ярус: детерминирован, не требует моделей, сети и БД, должен работать при недоступности остальных ярусов.
- Код отсутствует (CyberPipe.slnx пуст); проекты помечены как «к созданию».

## Объём работ

- Создать проект роутера (к созданию: `src/CyberPipe.Router/`) и реализацию Tier 0 по контрактам TASK-002.
- Загрузка набора правил из конфигурации (TASK-003): паттерн, intent, приоритет, параметры извлечения именованных групп.
- Сопоставление входного текста с правилами по приоритету; возврат первого совпадения с заполненными параметрами.
- Нормализация входа перед сопоставлением: trim, схлопывание пробелов, регистронезависимость по настройке правила.
- Защита от катастрофического бэктрекинга: тайм-аут на каждое regex (например, `Regex.MatchTimeout`), отклонение/пропуск правила при тайм-ауте с записью в лог.
- Метрики: число попаданий/промахов, время сопоставления (для диагностики, TASK-004).

## Контракты и интерфейсы

Используются абстракции из TASK-002 (точные имена — по факту TASK-002, ниже — требуемая семантика):

- `IRouterTier` / эквивалент: `Task<RouteResult> TryRouteAsync(RouteRequest request, CancellationToken ct)`.
- `RouteRequest`: текст, канал/источник, локаль, метаданные триггера.
- `RouteResult`: статус (`Matched` / `Escalate`), intent, параметры (`IReadOnlyDictionary<string,string>`), уверенность (для Tier 0: 1.0 при полном совпадении паттерна), имя сработавшего правила.
- `IRegexRuleProvider` (внутренний): отдаёт упорядоченный список правил из конфигурации.
- Правила не должны зависеть от конкретного канала (Telegram/Avalonia/CLI) — только от текста и метаданных.

## Результаты

- Работающий Tier 0 в проекте роутера (к созданию).

- Unit-тесты на сопоставление, приоритеты, эскалацию и тайм-ауты regex.

## Критерии приёмки

- Совпадение с правилом возвращает `Matched`, корректный intent и все именованные группы как параметры.
- Текст без совпадений возвращает `Escalate` без исключений.
- При нескольких совпадениях побеждает правило с наивысшим приоритетом; порядок стабилен.
- Патологический паттерн/вход не блокирует роутер дольше заданного тайм-аута; факт тайм-аута логируется.
- Пустой/whitespace вход возвращает `Escalate`.
- Роутер не обращается к БД, сети и моделям (проверяется тестом с фейками, фиксирующими вызовы).

## Тестирование

- Уровень: unit.
- Как: табличные тесты «вход → intent/параметры/Escalate»; фейковый `IRegexRuleProvider`; тест на тайм-аут с заведомо тяжёлым паттерном; тест отсутствия внешних зависимостей (строгие моки хранилищ/моделей не используются вообще).
