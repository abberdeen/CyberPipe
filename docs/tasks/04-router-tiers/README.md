# 04-router-tiers — Маршрутизация по ярусам (Tier 0–3)

## Назначение области

Область отвечает за выбор способа обработки входящего запроса в CyberPipe по возрастающей стоимости и сложности:

```text
Запрос → Tier 0 (regex) → Tier 1 (ONNX-эмбеддинги + семантический кэш)
       → Tier 2 (лёгкая LLM) → Tier 3 (тяжёлая LLM)
```

Каждый ярус либо даёт окончательный ответ / намерение (intent) с уверенностью выше порога, либо эскалирует запрос на следующий ярус. Перед обращением к LLM-ярусам проверяется бюджет токенов.

## Состав

| ID | Задача | Результат |
|---|---|---|
| TASK-030 | Tier 0 — regex-роутер | Мгновенное сопоставление по регулярным выражениям |
| TASK-031 | Tier 1 — семантический роутер | ONNX-эмбеддинги (multilingual-e5-small), классификация по близости |
| TASK-032 | Tier 2/3 — LLM-роутер | Лёгкая и тяжёлая LLM, эскалация по уверенности |
| TASK-033 | TokenBudgetGovernor | Дневной бюджет, лимиты токенов и числа ходов |
| TASK-034 | Семантический кэш | Кэш ответов по близости эмбеддингов в pgvector |

## Общие принципы

- Модели не встраиваются в приложение. Tier 1 использует локальную ONNX-модель `multilingual-e5-small`, предлагаемую при первом запуске; Tier 2/3 обращаются к моделям через абстракции из TASK-002 (локальные через Ollama или облачные — по конфигурации).
- Все пороги, лимиты и бюджеты конфигурируемы (см. TASK-003); значения по умолчанию — цели, а не жёсткие ворота качества.
- SLO по задержкам и точности являются целевыми ориентирами, а не блокирующими критериями приёмки.
- Код ещё не создан (CyberPipe.slnx пуст); пути проектов помечены как «к созданию».

## Порядок реализации

1. TASK-030 и TASK-033 — без зависимостей от данных, на моках контрактов TASK-002.
2. TASK-034 и TASK-031 — после готовности хранилища эмбеддингов TASK-012.
3. TASK-032 — после TASK-033 (проверка бюджета перед LLM-вызовами).
