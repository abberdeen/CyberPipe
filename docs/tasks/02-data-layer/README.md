# 02-data-layer — Слой данных (PostgreSQL + pgvector)

## Назначение области

Область отвечает за единственное хранилище CyberPipe: одну базу PostgreSQL с расширением pgvector. Отдельных баз, брокеров и файловых хранилищ состояния не вводится. В той же PostgreSQL позднее размещаются таблицы Quartz.NET (TASK-045) и контрольные точки цепочек (TASK-044), но их создание не входит в эту область.

```text
Service / Brainstem / Router
        │
        ▼
Репозитории (TASK-013) ──► Эмбеддинги pgvector (TASK-012)
        │                          │
        └──────────┬───────────────┘
                   ▼
        Схема и миграции (TASK-011)
                   │
                   ▼
        Подключение и bootstrap (TASK-010)
                   │
                   ▼
        PostgreSQL + pgvector (локальная установка)
```

## Состав

| ID | Задача | Результат |
|---|---|---|
| TASK-010 | Bootstrap PostgreSQL | Проверка/установка, подключение, запрос пароля при недоступности |
| TASK-011 | Схема и миграции | Версионируемая схема БД, идемпотентные миграции вверх/вниз |
| TASK-012 | Хранилище эмбеддингов pgvector | Сохранение векторов и семантический поиск по близости |
| TASK-013 | Репозитории и доступ к данным | Типизированные репозитории поверх схемы TASK-011/012 |

## Общие принципы

- Одна PostgreSQL + pgvector на всё приложение; SQLite и иные СУБД не используются.
- Пароль и строка подключения не хранятся в репозитории и не логируются; при невозможности подключения bootstrap запрашивает пароль у пользователя (TASK-010).
- Размерность векторов не зашивается в код жёстко: она берётся из конфигурации модели эмбеддингов (по умолчанию `multilingual-e5-small`, предлагается при первом запуске; модель не встроена в приложение).
- Все лимиты, пулы соединений и таймауты конфигурируемы (TASK-003); значения по умолчанию — цели, а не жёсткие ворота.
- Код ещё не создан (`CyberPipe.slnx` пуст); пути проектов помечены как «к созданию».
- Доступ только для роли Owner; понятия Guest нет.

## Порядок реализации

1. TASK-010 — подключение и проверка pgvector.
2. TASK-011 — схема и миграции поверх TASK-010.
3. TASK-012 — векторное хранилище поверх схемы TASK-011.
4. TASK-013 — репозитории поверх TASK-011 и TASK-012.
