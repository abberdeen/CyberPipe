# TASK-010 — Bootstrap PostgreSQL (установка, подключение, запрос пароля)

## Цель

Обеспечить воспроизводимый первый запуск единственной базы CyberPipe: обнаружить локальный PostgreSQL с pgvector, подключиться к нему и, если подключение невозможно, запросить пароль у пользователя и повторить попытку — без записи секретов в репозиторий и логи.

## Контекст

- CyberPipe (.NET 10) использует одну PostgreSQL + pgvector на всё приложение; других СУБД нет (DECISIONS.md, 17-adr-mvp.md OVERRIDE).
- В той же PostgreSQL позже живут Quartz.NET (TASK-045) и контрольные точки цепочек (TASK-044) — здесь создаётся только подключение и проверка расширений.
- Конфигурация и секреты — область TASK-003; контракты и абстракции сообщений — TASK-002. Код отсутствует (`CyberPipe.slnx` пуст), проекты помечены «к созданию».
- Ручное тестирование сфокусировано на Windows; Service устанавливается в `Program Files`, Desktop управляет Service отдельно.

## Объём работ

- Проект `src/CyberPipe.Data` (к созданию): `PostgresOptions` (хост, порт, база, пользователь, пул, таймауты; все значения конфигурируемы, пароль — только из секретов TASK-003/переменных окружения).
- `IPostgresBootstrapper` / `PostgresBootstrapper` (к созданию): проверка доступности сервера (`SELECT 1`), проверка/включение расширений `vector` (и `pgcrypto` при необходимости схемы), создание базы приложения, если отсутствует.
- Сценарий «не могу подключиться»: классифицировать причину (сервер не запущен, неверный пароль, нет прав, нет pgvector) и через абстракцию запроса секрета `ISecretPrompt` (контракт TASK-002/TASK-003, реализация UI — вне задачи) запросить пароль у пользователя, повторить подключение ограниченное число раз, далее — понятная ошибка без пароля в тексте.
- Инструкция/скрипт проверки локальной установки PostgreSQL + pgvector для Windows (к созданию, `docs/tasks/02-data-layer/` или `src/CyberPipe.Data/README` внутри проекта): как установить, как проверить `pg_extension`, что делать при отсутствии `vector`.
- Health-check подключения для Service: результат `Ready / Degraded(reason)` без секретов, пригодный для TASK-020 и TASK-063.
- Повторный запуск идемпотентен: не пересоздаёт базу, не сбрасывает данные, не меняет пароль пользователя.

## Вне рамок

- Установка PostgreSQL «в один клик» инсталлятором приложения и управление службой Windows — вне задачи; допускается только проверка и инструкция.
- Quartz, цепочки, HITL и любые пользовательские данные.

## Контракты и интерфейсы

- `PostgresOptions { Host, Port, Database, Username, Password (secret-ref), MaxPoolSize, CommandTimeout }` — к созданию в `src/CyberPipe.Data` (к созданию); пароль хранится только как ссылка на секрет TASK-003, не как значение в `appsettings.json`.
- `IPostgresBootstrapper.EnsureReadyAsync(CancellationToken) -> BootstrapResult` — к созданию; `BootstrapResult { Status: Ready|NeedsPassword|Unavailable, ReasonCode, ServerVersion, PgVectorVersion? }`, без секретов в полях.
- `ISecretPrompt.RequestPasswordAsync(purpose, CancellationToken) -> SecretString?` — контракт из TASK-002/TASK-003; в тестах заменяется фейком.
- `IPostgresConnectionFactory.CreateOpenedConnectionAsync(CancellationToken) -> NpgsqlConnection` — к созданию; единственный способ получать соединения для TASK-011–TASK-013.
- Ошибки: `PostgresUnavailableException(reasonCode)` без строки подключения и пароля в `Message`/логах.

## Результаты

- Работающий bootstrap: на машине с PostgreSQL + pgvector возвращает `Ready` с версиями сервера и расширения.
- При неверном/отсутствующем пароле — запрос пароля через `ISecretPrompt` и повторная попытка; при отказе пользователя — `NeedsPassword` без падения Service.
- Идемпотентность повторных запусков подтверждена тестом.
- Инструкция по локальной установке и диагностике pgvector для Windows.

## Критерии приёмки

- [ ] На чистом локальном PostgreSQL без базы приложения bootstrap создаёт базу, включает `vector` и возвращает `Ready`.
- [ ] При недоступном сервере возвращается `Unavailable` с кодом причины; пароль в логах, исключениях и результате отсутствует (проверяется тестом на фейковом промпте и захватом логов).
- [ ] При неверном пароле вызывается `ISecretPrompt` не более заданного числа раз; верный пароль из промпта приводит к `Ready`.
- [ ] Второй и последующие запуски не изменяют существующие данные и не требуют пароля при валидном секрете.
- [ ] Строка подключения собирается только из `PostgresOptions` + секрета; в репозитории нет захардкоженных паролей (проверка поиском по проекту).

## Тестирование

- Уровень: unit + integration.
- Unit: классификация ошибок подключения и логика повторов — на фейках `ISecretPrompt` и фабрики соединений, без реальной БД.
- Integration: Testcontainers PostgreSQL с pgvector (или локальный инстанс из переменной окружения) — создание базы, включение `vector`, идемпотентный повторный запуск, сценарий «неверный пароль → промпт → успех».
- Как: `dotnet test` соответствующего тестового проекта (к созданию); интеграционные тесты помечены категорией `Integration` и пропускаются без Docker/локальной БД с явным сообщением.
