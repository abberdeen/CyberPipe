## 1.1 System Purpose and Core Value Proposition

**CyberPipe** is a local-first, low-latency, token-frugal AI assistant and deterministic agent orchestrator designed to run on a developer's or knowledge worker's primary workstation or home server (**Windows 10/11** for MVP, with planned **Linux** and **macOS** portability).

Conventional agent frameworks route every user message—together with massive system prompts and dozens of tool schemas—to a paid cloud LLM, incurring 5–15 seconds of latency, high token costs, and severe host-safety risks (prompt injection, accidental file deletion, or secret exfiltration). CyberPipe solves this through four architectural pillars:
1. **Zero-Token Fast-Path Routing (`Tier 0` & `Tier 1`):** 70–85% of daily commands (media/volume control, timers, quick expense logging, Git repo status, and hybrid knowledge search) are resolved deterministically in C# (`Tier 0`) or via an in-memory local ONNX embedding router + SIMD cosine similarity (`Tier 1`) in `< 1–15 ms` with **0 cloud tokens (`$0.00`)**.
2. **User-Controlled Hybrid AI Tiers (`Tier 2` & `Tier 3`):** Users explicitly bind either a **local model (`Local` via Ollama / LM Studio, `$0.00`)** or a **paid cloud API (`RemoteCloud`)** to `Tier 2` (light JSON parameter extraction with Dynamic Tool Pruning) and `Tier 3` (complex coding, contract red-flag auditing, meeting summarization), guided by a hardware compatibility advisor (`IHardwareCapabilitiesProbe` + `IModelCompatibilityAdvisor`).
3. **Reusable Deterministic Automation (`Netrunner` Mini-n8n DAG Engine):** Recurring multi-step data pipelines are synthesized once into standardized 6-file ETL packages (`data/netrunner-packages/<slug>/<version>/`) and executed inside an 8-node Directed Acyclic Graph (`NetrunnerWorkflowDefinition`) with step checkpoints and Human-in-the-Loop (`HitlApprovalNode`) gates.
4. **Hardened Zero-Trust Host & Budget Guardrails:** Deterministic C# guards enforce numerical Telegram whitelisting (`Owner` vs `Guest`), no raw shell from chat, audio volume clamping (`<= 60%` day / `<= 25%` night + pre-playback check), physical tool stripping on untrusted external inputs (`Hard Tool Stripping`), egress secret redaction without blind rehydration (`CentralDataSanitizer`), out-of-process sandboxing (`CyberPipe.Brainstem`), and strict token budget limits (`TokenBudgetGovernor` with auto-pause and `< 50 ms` `/stop` kill-switch).

## 1.3 Business and Technical Goals

1. **Zero-Dependency Out-of-the-Box Startup (`< 1 s` cold start target):** Launch on a standard Windows 10/11 desktop in the user's interactive session (`Session >= 1`) without requiring Docker, PostgreSQL, or RabbitMQ to be installed (`REQ-010`, `REQ-017`).
2. **Order-of-Magnitude Token Cost Reduction (`70–85%` zero-token resolution):** Guarantee `$0.00` cloud spend on routine commands, voice transcription (`Whisper.net`), local RAG search (`KnowledgeVault`), and recurring ETL pipelines (`Netrunner`), while capping daily cloud spend via `TokenBudgetGovernor` (`Default $0.50/day`).
3. **Kernel-Enforced Host & Data Safety:** Prevent chat commands, prompt-injected documents, or hallucinating LLMs from wiping files, blasting loud/NSFW audio, reading `data/*.db` or `secrets.vault` from worker processes, or leaking API keys to cloud providers.
4. **Strict Modularity & Compile-Time Governance:** Prevent architectural erosion by enforcing a 16-project Directed Acyclic Graph (DAG) via `ArchUnitNET` and a CI `Publish Directory Layout Gate`.

## 1.4 Explicit Non-Goals (Out of Scope for MVP)

Per [`01-principles.md`](../../plans/01-principles.md), [`15-cli-and-execution-modes.md`](../../plans/15-cli-and-execution-modes.md), and [`17-adr-mvp.md`](../../plans/17-adr-mvp.md), the following are explicitly **non-goals**:

* **No Multi-Tenant Cloud SaaS Hosting:** CyberPipe is a single-owner local workstation/home-server daemon (with optional restricted family `Guest` access via Telegram), not a multi-tenant cloud SaaS platform.
* **No Windows `Session 0` System Service Execution:** Running `CyberPipe.exe` as a `Session 0` Windows Service is explicitly excluded because Windows isolates `Session 0` from interactive desktop audio (`WASAPI`), clipboard, and screen OCR (`Windows.Media.Ocr`).
* **No In-Process Generative LLM Weight Hosting Inside `Brainstem`:** Multi-gigabyte generative LLM weights (`Tier 2` / `Tier 3` local models) are delegated to an external local HTTP server (`Ollama` / `LM Studio` on `localhost:11434`), not loaded via `LLamaSharp` inside `CyberPipe.Brainstem.exe`.
* **No Mandatory External Brokers or Container Engines at Startup:** `RabbitMQ`, `Docker`, and `Wasmtime` are optional extensions behind separate ADRs (`ADR-001`, `AUD-10`), not baseline MVP startup dependencies.
* **No Raw Shell Access from Telegram:** Direct execution of arbitrary `powershell`, `cmd`, or `bash` strings from chat messages is permanently prohibited (`HostSafetyGuard`).
* **No Linux / macOS Parity in Initial MVP Release (`L4`):** While platform interfaces (`IBrainstemIsolationPlatform`, `IAudioDeviceController`, `ISecretVaultPlatform`, `IScreenOcrProvider`, `IDaemonInstaller`) are abstracted in `CyberPipe.Contracts`, the initial MVP targets **Windows 10/11 only**; Linux (`bwrap`) and macOS (`Seatbelt`) implementations are deferred to post-MVP (`K.4`).
