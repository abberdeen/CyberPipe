## 4.1 Core Architectural Approaches and Design Decisions

CyberPipe's architecture is driven by four primary tensions: **sub-20ms responsiveness vs. rich AI capabilities**, **remote Telegram convenience vs. absolute host safety**, **untrusted file/code execution vs. daemon stability**, and **zero-dependency startup vs. durable workflow state**.

The table below maps each primary quality goal and requirement to the concrete architectural strategy chosen in [`docs/plans/`](../../plans/README.md), alongside the critical caveats identified during our architectural evaluation:

| Architectural Driver | Solution Strategy | Governing ADRs & Risks |
| :--- | :--- | :--- |
| **1. Radical Token & Latency Reduction (`REQ-001`, `REQ-014`, `QAS-001`, `QAS-002`)** | **4-Tier Cascading Intent Router + Netrunner Deterministic ETL:**<br/>• **Pre-Router:** Local `Whisper.net` ONNX speech-to-text in a warm `Brainstem` worker pool (`0` cloud tokens).<br/>• **`Tier 0` (`< 1 ms`):** Regex & slash commands invoke compiled `IHostSkill` classes directly.<br/>• **`Tier 1` (`5–15 ms`):** In-process `ONNX Runtime` (`multilingual-e5-small`) + `.NET 10` `TensorPrimitives.CosineSimilarity` over a flat `Memory<float>` buffer (`~15 MB` for 10k records) + `SemanticIntentCache` and role-scoped `SemanticResponseCache` keyed by `(QueryHash, UserRole, DataVersion, ExpiresAtUtc)`.<br/>• **`Tier 2` / `Tier 3`:** Invoked only on cache/intent miss (`~15–20%` of requests) with **Dynamic Tool Pruning** (top 2–3 tools + top 3 trusted RAG facts, reducing prompt size from `~8,000` to `~250` tokens).<br/>• **Netrunner Mini-n8n DAGs:** Synthesize recurring tasks once using `Tier 3`, validate against `schema.input.json`/`schema.output.json` and `sample.fixture.json`, and run forever at `0` tokens (`SkillNode` $\to$ `NetrunnerScriptNode` $\to$ `ConditionNode`). | [`ADR-0001`](../05-adr/0001-example-decision.md), [`ADR-0007`](../05-adr/0007-proactive-scheduling-and-netrunner-dag-engine.md)<br/>Risks: `RISK-003` (Roslyn `64 MB` OOM), `RISK-010` (`DataVersion` invalidation), `RISK-011` (in-process ONNX crash radius). |
| **2. Financial & Resource Predictability (`REQ-002`, `REQ-003`, `REQ-004`, `QAS-003`, `QAS-009`)** | **Mandatory `TokenBudgetGovernor` Middleware + Hardware Advisor + Priority Kill-Switch:**<br/>• Wrap every `IChatClient` in `TokenBudgetGovernor`: pre-flight token estimate (`Microsoft.ML.Tokenizers` `o200k_base` with `1.2x` Cyrillic multiplier), hard `ChatOptions.MaxOutputTokens = Math.Min(2048, remaining)` against reasoning-model token explosions, auto-pause (`TaskLifecycleState.PausedByBudget`) at `4,000` tokens or `3` turns with Telegram inline buttons (`+5,000` tokens / `+3` turns up to `HardTaskTokenLimit = 12,000`), and `15,000` tokens/min velocity circuit breaker.<br/>• Distinguish `ModelHostingType.Local` (`$0.00`, RAM/VRAM guarded by `ISystemResourceMonitor` & `IModelCompatibilityAdvisor`) from `RemoteCloud` (`$` ledger in `budget.db`).<br/>• Route `/stop` and `/pause` via out-of-band `PriorityControlChannel` to trigger `CancellationTokenSource.Cancel()` and `JobObject` kill in `< 50 ms`. | [`ADR-0008`](../05-adr/0008-token-budget-governance-and-crash-recovery.md)<br/>Risks: `RISK-015` (unverified SLOs), `RISK-016` (`MaxLlmTurnsPerTask` `3` vs `5` drift). |
| **3. Host Safety Against Abuse & Prompt Injection (`REQ-005`, `REQ-006`, `REQ-007`, `REQ-008`, `QAS-007`, `QAS-008`, `QAS-014`)** | **Defense-in-Depth Deterministic C# Guards (`0` LLM Tokens):**<br/>• **Perimeter:** Numerical `TelegramUserId` whitelist (`Owner` vs `Guest`); `< 0.1 ms` drop for strangers.<br/>• **Anti-Wipe & Audio Guard:** No raw shell from chat; compiled `IHostSkill`s only; `VolumeClamp` (`60%` day / `25%` night, max `+20%` jump) + mandatory `EnsureSafeVolumeBeforePlayback()` before `Play`/`Resume`; media provider whitelist + Unicode `FormKC` NSFW filter.<br/>• **Taint Propagation (`MemoryTrustSource`):** Any `UntrustedExternal` input switches session to `TaintedContext` and physically strips all host-mutating tools from `ChatOptions.Tools` (`Hard Tool Stripping`).<br/>• **Egress Sanitization:** `CentralDataSanitizer` redacts secrets (`[REDACTED:TYPE:ID]`) before `RemoteCloud`, `Serilog`, and `Telegram` without mutating local ingress data and **without automatic string rehydration**. | [`ADR-0001`](../05-adr/0001-example-decision.md), [`ADR-0004`](../05-adr/0004-brainstem-process-isolation-and-sandboxing.md), [`ADR-0006`](../05-adr/0006-secrets-vault-and-egress-sanitization.md)<br/>Risks: `RISK-007` (`dotnet`/`git` execution), `RISK-012` (false DNS `1.1.1.3` assumption). |

## 4.2 Strategy Reconciliation Required in Phase 0

Before writing Sprint 1 code, the solution strategy requires four targeted technical corrections (detailed in [`05-adr/`](../05-adr/README.md) and [`06-validation/technology-compatibility-matrix.md`](../06-validation/technology-compatibility-matrix.md)):

1. **Replace Non-Existent `MassTransit.SqlTransport.Sqlite` (`RISK-001`, [`ADR-0002`](../05-adr/0002-message-bus-and-transport-strategy.md)):** Keep `MassTransit` v8 (`InMemory`) for MVP in-process dispatch and rely on `budget.db` (`TaskCheckpoints`), `netrunner.db` (`NetrunnerStepRuns`), and `InFlightOperations` for crash durability—or implement a custom SQLite Outbox over `masstransit.db` rather than referencing a non-existent NuGet package. Require daemon restart (or an explicit child-container `IBusControl` proxy) when switching to enterprise `RabbitMQ`.
2. **Unify SQLite Native Provider on `Microsoft.Data.Sqlite.Core` + `SQLitePCLRaw.bundle_e_sqlcipher` (`RISK-002`, `RISK-005`, [`ADR-0003`](../05-adr/0003-decentralized-sqlite-and-sqlcipher-encryption.md)):** Remove direct references to `Microsoft.Data.Sqlite` (which pulls `bundle_e_sqlite3`) and avoid `Hangfire.Storage.SQLite`'s default `bundle_green` conflict; use `Cache=Private;Pooling=True` instead of `Cache=Shared`.
3. **Assign Explicit Database Homes for Orphan Tables (`RISK-008`, [`ADR-0003`](../05-adr/0003-decentralized-sqlite-and-sqlcipher-encryption.md)):** Place `InFlightOperations` in `health.db` (or `budget.db`) and `SemanticIntentCache` / `SemanticResponseCache` in `knowledge.db`.
4. **Pre-Compile Netrunner `CSharpRoslyn` Packages on the Host (`RISK-003`, [`ADR-0007`](../05-adr/0007-proactive-scheduling-and-netrunner-dag-engine.md)):** Compile `main.csx` during package validation (`NetrunnerPackageValidator`) into a restricted assembly `.dll` (or `.wasm` module) so that runtime execution inside the `64 MB` sandbox does not load the `150–300 MB` Roslyn compiler into the worker's memory space.
