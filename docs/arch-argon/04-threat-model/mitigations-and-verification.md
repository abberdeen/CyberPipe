# Threat Model: Mitigations, Implementation Status, and Security Verification

> **Document Role:** Consolidates all security controls required to mitigate `THREAT-001`..`THREAT-016`, explicitly distinguishing between **Enforced by Existing Code (`0`)**, **Proposed in `docs/plans/`**, and **Additional Controls Recommended by `arch-argon`**, and mapping every control to an automated verification test (`TEST-001`..`TEST-015`).

---

## 1. Epistemic Classification of Security Controls

Per Section 7.4 of the architecture mandate, security controls must never be presented as already implemented when they exist only in planning documents:

- **Enforced by Code (`0` Controls):** `CyberPipe.slnx` currently contains `0` `.cs` files (`RISK-004`). **No security control is currently active in compiled code.**
- **Proposed in `docs/plans/` (`12` Core Controls):** Specified in `05-security-and-zero-trust.md`, `06-sandbox-and-process-execution.md`, `09-data-protection-and-state-hub.md`, and `15-cli-and-execution-modes.md`, but several contain hidden flaws (`RISK-002`, `RISK-003`, `RISK-006`, `RISK-007`, `RISK-009`) that would cause them to fail if implemented verbatim.
- **Recommended / Corrected by `arch-argon` (`11` Hardening Controls):** Specific architectural corrections required to make the proposed controls sound, verifiable, and non-bypassable.

## 3. Summary of Residual Risks & Operational Limitations

Even with all 12 mitigations (`MIT-01`..`MIT-12`) implemented and verified, the following residual risks remain inherent to a local workstation assistant and must be accepted by the Owner:

1. **Same-User Malware Outside Sandboxes (`TB-02`):** Any third-party application running natively as the interactive Owner on the same Windows desktop (outside CyberPipe's `AppContainer`/`RestrictedToken` sandboxes) shares the Owner's Windows SID and `DPAPI` `CurrentUser` context. CyberPipe protects the host *from* untrusted inputs, LLMs, and child workers (`TB-01`, `TB-04`, `TB-05`), but cannot protect against an already-compromised host desktop session.
2. **Unstructured Semantic PII in Cloud Prompts (`TB-01`):** While `CentralDataSanitizer` deterministically scrubs structured secrets, tokens, credit cards, SSNs, emails, phones, and file paths (`QAS-008`), free-form narrative facts (e.g., *"I met with my doctor about my knee surgery"*) cannot be redacted by regexes without destroying prompt meaning. Sensitive domains (`health.db`, `finance.db`) should therefore be configured with `"PrivacyTier": "LocalOnly"` in `ModelRouter` (`REQ-003`).
3. **Manipulated Text Summaries from Tainted Data (`THREAT-001`):** Hard Tool Stripping (`MIT-01`) guarantees `0` unauthorized tool calls on `UntrustedExternal` data (`QAS-007`), but an adversarial web page or email can still cause the LLM to return a misleading text summary to the user.
