# 12. Каталог функций и системных возможностей: Личный, Инженерный и Бизнес-Помощник

Архитектура **CyberPipe** (`4-Tier Intent Router` + `SQLite WAL` + `Zero-Trust Guards`) позволяет превратить оркестратор из простого исполнителя команд в **незаменимого ежедневного ассистента («Второй мозг + Шеф-инженер + Бизнес-операционист»)**.

Главный принцип: **80–90% ежедневных задач решаются локально (`Tier 0 / Tier 1 / Tier 2`) за миллисекунды с расходом 0 облачных токенов**, а тяжелый интеллект (`Tier 3`) подключается точечно под контролем `TokenBudgetGovernor` и `SecurityGuard`.

---

## 1. Системные возможности ядра (Core & System Capabilities)

### 1.1. Локальный голосовой конвейер (`0$ Voice-to-Intent`)
* **Задача:** Управлять помощником на ходу через голосовые сообщения в Telegram или горячую клавишу на ПК без оплаты облачного Speech-to-Text.
* **Реализация:** Встроенный перед роутером модуль на базе **`Whisper.net` (ONNX / GGML)** транскрибирует аудио локально на CPU/GPU за `0.3–0.8 сек` (**0 токенов**). Полученный текст сразу поступает в `Tier 0 / Tier 1`.
* **Примеры:** *«Поставь напоминание позвонить клиенту в 15:00»*, *«Запиши идею для фичи в проект X»*, *«Сделай звук потише и включи режим фокуса»*.

### 1.2. Проактивный движок расписаний, системные и пользовательские задачи (`ProactiveScheduler & UserAutomations`)
* **Задача:** Помощник не просто ждет команд, а сам вовремя предупреждает, собирает сводки, реагирует на события ОС, Git и инфраструктуры, а также исполняет **произвольные пользовательские расписания и сценарии автоматизации**.
* **Реализация:** Промышленный планировщик на базе **`Hangfire`** с хранением задач в **отдельной зашифрованной паролем базе `data/subsystems/hangfire.db`**, локальным защищенным **Read-Only Dashboard** на `127.0.0.1` (авторизация по одноразовому токену + HttpOnly cookie) и разделением задач на два класса:

#### А. Системные встроенные задачи (System Built-in Tasks):
1. **По расписанию (Cron/Recurring):** утренний исполнительный брифинг (`09:00`, `0 9 * * *`), вечернее подведение итогов (`20:00`, `0 20 * * *`), контроль оплаты подписок (за 3 дня до списания), регулярный аудит инфраструктуры (`InfraHealthWatchdog`).
2. **По системным событиям (Watchdogs):** завершение долгой сборки/тестов (`BuildAndTestWatchdog`), падение рабочего контейнера/API/SSL, перегрев GPU/CPU.
3. **Условные цепочки (If-This-Then-That за 0 токенов):** *«Когда закончится `dotnet test`, пришли результат в Telegram»*.

#### Б. Пользовательские задачи и автоматизации (`User Scheduled Tasks & Automations`):
Пользователь может создавать собственные расписания и периодические задачи тремя способами:
1. **Через Telegram (естественный язык или команды):**
   * *«Напоминай каждый рабочий день в 10:00 проверять почту клиента X»*
   * *«Каждые 30 минут проверяй доступность https://api.myproject.com и пингуй, если лежит»*
   * *«Каждое воскресенье в 19:00 собери сводку по расходам за неделю»*
   * Команды: `/schedule list`, `/schedule pause <id>`, `/schedule resume <id>`, `/schedule delete <id>`.
2. **Через Avalonia Desktop UI (Вкладка «Планировщик и Автоматизации»):**
   * Визуальный конструктор расписания: выбор интервала, времени, дней недели или прямой ввод Cron-выражения (`CronExpression`).
   * Кнопка ручного тестирования `[▶️ Запустить сейчас]`.
   * Переключатель Вкл/Выкл (`IsEnabled`) и журнал последних запусков (дата, длительность, статус Успех/Ошибка).
3. **Через системный CLI (`CyberPipe schedule`):**
   * `cyberpipe schedule list` — список всех активных пользовательских расписаний.
   * `cyberpipe schedule add --title "Weekly Report" --cron "0 18 * * 5" --action prompt --payload "Сделай выжимку выполненных задач"`

#### Поддерживаемые типы действий в пользовательских задачах:
* **`NotificationAction` (Напоминание / Опрос):** отправка текстового напоминания в Telegram и Desktop UI с интерактивными инлайн-кнопками (`[✅ Выполнено]`, `[⏰ Отложить на 15 мин]`).
* **`SkillAction` (Вызов C#-скилла за 0 токенов):** вызов любого локального детерминированного скилла (проверка Git-репозиториев `/repos`, снятие бэкапа, замер громкости, проверка здоровья URL/SSL).
* **`NetrunnerAction` (Детерминированный ETL-скрипт Netrunner за 0 токенов):** выполнение собственного скрипта из базы ассистента Netrunner (`data/subsystems/netrunner.db`). Исключает повторные обращения к ИИ для повторяющихся рутинных парсингов (например, курсы валют, выгрузка сводок, фильтрация прайс-листов). Может работать в конвейере с `SkillAction` (скилл забирает сырые данные ➔ Netrunner производит ETL-обработку и агрегацию ➔ результат отправляется пользователю).
* **`LlmPromptAction` (ИИ-исследование / Агентный промпт):** запуск анализа с помощью ИИ (например: *«Каждое утро в 08:30 сделай выжимку трендов по теме X»*). Строго лимитируется `TokenBudgetGovernor` по мягкому/жесткому бюджету токенов и списывается с дневной квоты.
* **`DevToolAction` (Фоновая разработка):** автоматический запуск `dotnet test` или линтера в разрешенном каталоге репозитория через `IDevToolProcessRunner` с отправкой только выжимки ошибок при падении.

#### Таблица пользовательских задач в БД (`UserScheduledTasks` в `hangfire.db`):
```sql
CREATE TABLE IF NOT EXISTS UserScheduledTasks (
    Id TEXT PRIMARY KEY,                 -- GUID задачи
    Title TEXT NOT NULL,                 -- Человекочитаемое название
    CronExpression TEXT,                 -- Cron-расписание (null для однократных delayed-задач)
    DueTimeUtc TEXT,                     -- Точное время для однократных отложенных задач
    ActionType TEXT NOT NULL,            -- 'Notification', 'Skill', 'Netrunner', 'LlmPrompt', 'DevTool'
    PayloadJson TEXT NOT NULL,           -- Параметры действия (NetrunnerScriptId, промпт, скилл, URL, аргументы)
    IsEnabled INTEGER NOT NULL DEFAULT 1,-- 1 / 0
    CreatedAtUtc TEXT NOT NULL,
    LastRunAtUtc TEXT,
    NextRunAtUtc TEXT,
    LastResultStatus TEXT,               -- 'Success', 'Failed', 'Skipped'
    LastErrorMessage TEXT
);
CREATE INDEX IF NOT EXISTS idx_user_tasks_enabled ON UserScheduledTasks(IsEnabled, NextRunAtUtc);
```

### 1.3. Долговременная память и Личный Граф Знаний (`KnowledgeVault`: `SQLite FTS5` + `SIMD Vectors`)
* **Задача:** Помнить контекст проектов, факты, заметки, контакты, сниппеты кода и договоренности месяцами, не раздувая контекстное окно LLM.
* **Реализация:** Использование уже загруженной в `Tier 1` модели эмбеддингов (`multilingual-e5-small`) и `TensorPrimitives.CosineSimilarity` в связке с полнотекстовым индексом **`SQLite FTS5`**.
  * Поиск по личной базе знаний за `5–15 мс` стоит **0 токенов**.
  * При вызове `Tier 2 / Tier 3` в промпт автоматически подмешиваются только топ-3 релевантных факта из памяти (`~150 токенов`).

### 1.4. Контекст Буфера обмена и Экрана (`Clipboard & Screen OCR Skill`)
* **Задача:** Мгновенно обрабатывать то, с чем пользователь работает прямо сейчас на ПК.
* **Реализация:** Кроссплатформенный локальный OCR через `IScreenOcrProvider` (`Windows.Media.Ocr` на Windows / `Tesseract` на Linux / `Vision Framework` на macOS за 0 токенов) + чтение буфера обмена строго по явной команде владельца (`Owner`) с обязательной очисткой через `CentralDataSanitizer` на Egress-границе при передаче в `RemoteCloud` или логи.
* **Примеры:** *«Переведи текст из буфера»*, *«Вытащи реквизиты счета со скриншота в буфере»*, *«Объясни стектрейс ошибки из буфера обмена»*.

### 1.5. Рабочие профили и Сцены (`Deterministic Workspace Profiles` — `Tier 0`, 0 токенов)
* **Задача:** Одной командой переключать ПК между режимами работы.
* **Реализация:** Скомпилированный C#-скилл `WorkspaceProfileSkill` (через кроссплатформенный `IAudioDeviceController` и `HostAndMediaSafetyGuard.EnsureSafeVolumeBeforePlayback()`):
  * `/mode coding` — закрывает лишние вкладки/мессенджеры, включает фоновый плейлист на `20%`, открывает терминал/IDE, включает перехват уведомлений.
  * `/mode call` — ставит музыку на паузу, проверяет активный микрофон/наушники через `IAudioDeviceController` (`NAudio` / `PipeWire` / `CoreAudio`), включает запись встречи по запросу.
  * `/mode relax` — приглушает системные алерты, переключает аудиовыход и освещение/тему.

## 2. Личные дела и управление ПК (`CyberPipe.Skills.Personal`)

### 2.1. Мгновенный Инбокс «Второго мозга» (`SecondBrainInboxSkill`)
* **Что делает:** Принимает в Telegram пересланные сообщения, ссылки, голосовые заметки, фотографии чеков/документов и текстовые мысли.
* **Как работает:** Локальный классификатор (`Tier 1 / Tier 2`) автоматически расставляет теги (`#идея`, `#купить`, `#прочитать`, `#финансы`, `#код`), сохраняет в `SQLite KnowledgeVault` (с обязательным сохранением метки происхождения `TrustSource = TrustedOwner` для личных заметок или `UntrustedExternal` для пересланных извне ссылок/текстов) и индексирует вектором.
* **Мгновенный поиск (`0 токенов`):** *«Найди, куда я сохранял ссылку на библиотеку графиков»* или *«Какой размер обуви я записывал в прошлом месяце?»*.

### 2.2. Умные напоминания с подтверждением (`PersistentReminderSkill`)
* **Что делает:** Поддерживает однократные, периодические и «настойчивые» напоминания.
* **Как работает:** Для критичных бытовых задач (*«Выключить духовку через 30 минут»*, *«Принять лекарство»*) бот пингует в Telegram каждые 2 минуты, пока пользователь не нажмет инлайн-кнопку `[✅ Выполнено]` или `[⏰ Отложить на 10 мин]`.

### 2.3. Финансовый радар, Учет расходов и Контроль подписок (`FinanceAndSubscriptionsSkill`)
* **Быстрый учет (`Tier 0 / Tier 1`, 0 токенов):** Команды вида *«кофе 350»*, *«бензин 2500»*, *«доход проект А 150000»* мгновенно парсятся и записываются в локальную таблицу `FinanceLedger`.
* **Радар подписок:** Хранит список всех регулярных списаний (сервисы, SaaS, домены, VPS, домашний интернет) и за **3 дня до списания** присылает уведомление в Telegram, чтобы вы успели отменить ненужную подписку или пополнить карту.

### 2.4. Тайм-менеджмент, Фокус и Забота о здоровье (`FocusAndHealthSkill`)
* **Помодоро и Фокус-сессии (`/focus 50m`):** Запускает таймер глубокой работы, приглушает громкость медиа, ведет статистику продуктивных часов за неделю в SQLite.
* **Контроль усталости:** Мягкие напоминания размяться и сделать перерыв для глаз при непрерывной работе за ПК более 90 минут.

### 2.5. Безопасный удаленный компаньон ПК (`RemoteHostCompanionSkill`)
* **Команды безопасности (`Tier 0`, 0 токенов):** `/lock` (мгновенная блокировка экрана Windows/Linux/macOS), `/sleep` (перевод ПК в сон), `/status` (аптайм, температура CPU/GPU, свободное место на дисках, активные задачи).
* **Безопасная выгрузка рабочих файлов (`/getfile`):** Доступ строго к белому списку папок (`AllowedShareDirectories`, например `%USERPROFILE%/Documents/Exports`) с проверкой через `HostSafetyGuard` и Egress-фильтрацией через `CentralDataSanitizer` (системные папки и файлы с ключами `.env` / `.ssh` физически недоступны).

## 3. Программирование и DevOps (`CyberPipe.Skills.Dev` & `Agents.Coder`)

### 3.1. Мульти-репозиторный Git-Радар (`GitRepoRadarSkill` — `Tier 0 / Tier 1`, 0 токенов)
* **Что делает:** Сканирует рабочую директорию (`%USERPROFILE%/source/repos` / `~/source/repos`) в режиме Read-Only через библиотеку `LibGit2Sharp` (либо через строго типизированный шлюз `IDevToolProcessRunner` из `CyberPipe.Execution.Providers`, без прямого доступа скилла к `System.Diagnostics.Process` или `CliWrap`).
* **Возможности за 0 токенов:**
  * `/repos` — список всех проектов: где есть незакоммиченные файлы (`dirty`), какая ветка активна, где есть неотправленные коммиты (`ahead/behind`).
  * `/standup` — собирает все ваши коммиты по всем репозиториям за последние 24 часа в готовую сводку для дейли-митинга или отчета клиенту.

### 3.2. Фоновый сборщик, Тест-раннер и Хирург ошибок (`BuildAndTestWatchdog`)
* **Что делает:** Запускает `dotnet build` / `dotnet test` через изолированный сервис `IDevToolProcessRunner` (`CyberPipe.Execution.Providers`) с жестким белым списком подкоманд и рабочим каталогом из `AllowedRepoRoots` по команде из чата или по триггеру.
* **Экономия токенов:** Вывод компилятора проходит через `QuotaBoundedStream` и `ToolOutputTruncator` (обрезается весь информационный шум, остаются только строки `error CS...` и `StackTrace` упавших тестов).
* **Интерактивный фикс:** В Telegram приходит компактный отчет об ошибке с кнопкой `[🛠 Найти причину и предложить патч (Tier 3)]`.

### 3.3. Пре-ревью диффов и Генератор коммитов (`DiffReviewSkill` — `Tier 2 / Tier 3`)
* **Что делает:** Перед отправкой кода анализирует `git diff`:
  * Локально (`0 токенов`) проверяет наличие забытых секретов (`Sanitizer`), маркеров `TODO/HACK`, отладочных `Console.WriteLine`.
  * Через `Tier 2` (`IChatClient` [`ModelTaskCategory.LightFastTier2`]) генерирует осмысленный `Conventional Commit` и описание Pull Request.
  * По запросу (`Tier 3` [`ModelTaskCategory.HeavyReasoningTier3`]) проводит ревью логики, потокобезопасности и соответствия архитектурным правилам (`ArchUnitNET`).

### 3.4. Мониторинг инфраструктуры, Docker и SSL (`InfraHealthWatchdog` — `0 токенов`)
* **Что делает:** Фоновый C#-сервис проверяет доступность ваших пет-проектов, продакшен-API, контейнеров Docker, баз данных и срок действия SSL-сертификатов / доменов.
* **Реакция на сбой:** Если сервис не отвечает или вернул `5xx`, в Telegram мгновенно прилетает алерт с последними 15 строками лога (очищенными от паролей через Egress `CentralDataSanitizer`) и кнопками `[🔄 Перезапустить контейнер]` / `[📋 Показать лог]`.

### 3.5. Личная база решенных багов и сниппетов (`DevMemorySkill` — `Tier 1`, 0 токенов)
* **Что делает:** Команда `/remember-fix` сохраняет текст редкой ошибки и способ её решения в локальную векторную базу `SQLite` (`TrustSource = TrustedOwner`).
* **Выгода:** При повторном возникновении похожей ошибки через полгода `Tier 1 Router` находит ваше решение за `< 10 мс` и **0 токенов**, не тратя время на повторный гуглинг.

### 3.6. Изолированный запуск одноразовых утилит и парсеров (`SandboxScriptRunner`)
* **Что делает:** Позволяет поставить задачу: *«Сконвертируй этот JSON-лог в Excel-таблицу и посчитай дубликаты»*.
* **Безопасность:** Агент `Tier 3` пишет скрипт, `SecurityGuard` проверяет его AST-дерево и ставит задачу на обязательное подтверждение владельцем (`SecurityVerdict.RequiresApproval` — HITL), после чего `ISandboxProvider` (`Wasmtime` / `Docker --network none` / `OS Restricted Sandbox`) выполняет код над копией файла в `EphemeralWorkspace` и возвращает готовый файл в Telegram.

## 4. Бизнес, Операционка и Коммуникации (`CyberPipe.Skills.Business`)

### 4.1. Утренний и Вечерний Исполнительный Брифинг (`ExecutiveBriefingSkill`)
* **Утренний дайджест (09:00, `0–200 токенов`):**
  * Встречи и дедлайны на сегодня.
  * Напоминания по клиентам (кому нужно написать Follow-up).
  * Предстоящие списания по подпискам и курсы валют.
  * Статус всех рабочих серверов и остаток бюджета токенов.
* **Вечернее ревью (20:00):** Сводка выполненных задач, сделанных коммитов в Git и список незакрытых вопросов, которые можно одной кнопкой `[➡️ Перенести на завтра]` сдвинуть в расписании.

### 4.2. Персональная CRM и Трекер договоренностей (`PersonalCrmSkill`)
* **Что делает:** Легковесная база контактов, клиентов, подрядчиков и партнеров в `SQLite`.
* **Возможности:**
  * Хранение контекста: *«Кто это, какой стек/проект, часовая ставка, о чем договорились на последнем созвоне»*.
  * **Авто-контроль ответов (`Waiting-For Tracker`):** *«Отправил КП Алексею, напомни в четверг, если не ответит»* — помощник сам поднимет карточку клиента в нужный день.

### 4.3. Запись созвонов и Выжимка договоренностей (`MeetingAssistantSkill`)
* **Захват аудио (`0 токенов`):** Использует кроссплатформенный `IAudioDeviceController` (**`NAudio` WASAPI Loopback + Microphone** на Windows / `PipeWire` на Linux / `CoreAudio` на macOS) для записи звука созвона (Zoom, Google Meet, Telegram, Teams) локально на диск.
* **Локальная расшифровка (`0$ Cloud Cost`):** По окончании звонка `Whisper.net` в изолированном процессе `CyberPipe.Brainstem` локально переводит аудио в текст с таймкодами.
* **Структурированный протокол (`Tier 2 / Tier 3`):** Выделяет из текста:
  1. Краткое резюме встречи (3–5 пунктов).
  2. Согласованные суммы, сроки и технические требования.
  3. Список задач (**Action Items**) с инлайн-кнопкой `[➕ Сохранить задачи в трекер]`.

### 4.4. Аудит договоров, ТЗ и счетов (`ContractRedFlagScanner`)
* **Что делает:** При отправке в Telegram файла `.pdf` или `.docx` изолированный одноразовый воркер `CyberPipe.Brainstem` (`SingleUseProcess = true`) извлекает текст (`PdfPig` / `OpenXml`), маркирует его как `MemoryTrustSource.UntrustedExternal` (с активацией `Hard Tool Stripping` — полным удалением всех мутирующих тулов из `ChatOptions.Tools`), при отправке в `RemoteCloud` маскирует чувствительные персональные данные через Egress `CentralDataSanitizer` и проверяет документ по вашему списку рисков:
  * Неограниченная ответственность и скрытые пени/штрафы.
  * Размытые критерии приемки работ или отсутствие аванса.
  * Несоответствие итоговых сумм в спецификации.

### 4.5. Быстрый генератор КП, счетов и деловых писем (`BusinessTemplateSkill`)
* **Что делает:** По короткой голосовой или текстовой команде (*«Собери черновик оценки для клиента Y: 3 спринта, .NET бэкенд + интеграция, ставка Z»*) заполняет локальный шаблон Markdown/DOCX/PDF и присылает готовый документ в чат.

### 4.6. Пассивная рыночная и технологическая разведка (`MarketOsintDigestSkill`)
* **Что делает:** В фоновом режиме (через безопасный `Passive OSINT` / RSS / GitHub Releases / публичные API) собирает новости по вашим темам, маркирует внешние тексты как `MemoryTrustSource.UntrustedExternal`, фильтрует информационный шум локальной векторной моделью (`Tier 1`, `Cosine >= 0.82`, **0 токенов на отсев мусора**) и раз в день присылает только действительно важные изменения (при суммаризации через `Tier 2 / Tier 3` действует `Hard Tool Stripping`).

## 5. Специализированный ETL-Ассистент Netrunner и Движок Каскадных Задач (`Mini-n8n DAG + HITL`)

> [!IMPORTANT]
> Полная спецификация движка каскадных задач, Human-in-the-Loop, таблиц БД и стандарта пакетов описана в документе [**`16-netrunner-etl-and-workflow-engine.md`**](file:///c:/Users/Conqueror/source/repos/CyberPipeline/docs/plans/16-netrunner-etl-and-workflow-engine.md) и оформлена в виде проектного скилла [`.agents/skills/netrunner-script-package/SKILL.md`](file:///c:/Users/Conqueror/source/repos/CyberPipeline/.agents/skills/netrunner-script-package/SKILL.md).

В приложении выделен отдельный автономный раздел и ассистент — **Netrunner**. Его ключевая миссия: **радикальное сокращение расхода токенов за счет превращения повторяющихся запросов к ИИ в стандартизированные ETL-пакеты и надежные каскадные графы задач (Mini-n8n DAG)**.

```
  [Триггер: Cron / Голос / Событие]
                │
                ▼
  [1. SkillNode (Fetch, 0$)] ────────► Скачивание сырого HTML / XML / API / логов
                │
                ▼
  [2. NetrunnerScriptNode (ETL, 0$)] ► Пакет <slug>@<version>: парсинг 5 000 строк ➔ 3 записи
                │                      (Валидация schema.input.json / schema.output.json)
                ▼
  [3. ConditionNode (0$)] ───────────► Дельта < порога? ──► [Тихое завершение за 0 токенов]
                │ (Дельта >= порога)
                ▼
  [4. LlmProcessNode (Опционально)] ─► ИИ анализирует ТОЛЬКО 3 отфильтрованные строки (~98% экономии!)
                │
                ▼
  [5. HitlApprovalNode (HITL)] ──────► Пауза + чекпоинт в netrunner.db + кнопки в Telegram/UI:
                │                      [✅ Одобрить]  [✏️ Изменить]  [🛑 Отклонить]
                ▼
  [6. DeliveryNode (Load, 0$)] ──────► Отправка отчета / файла в Telegram, запись в CRM / Финансы
```

### 5.1. Стандартизированный формат пакета скрипта Netrunner (6 обязательных файлов):
Каждый скрипт Netrunner хранится в папке `data/netrunner-packages/<slug>/<version>/` и обязан содержать **6 файлов** (проверяется сервисом `INetrunnerPackageValidator`):
1. **`netrunner.manifest.json`** — аналог `package.json`: описывает `slug`, `version`, `runtime` (`CSharpRoslyn` / `PythonSandbox` / `JavaScript`), входные и выходные MIME-форматы (`inputFormats`, `outputFormats`), контракты входных и выходных файлов (`inputFiles`, `outputFiles`), права песочницы и SHA-256 хеши всех файлов.
2. **`SKILL.md`** — паспорт скилла и список фраз-триггеров (индексируется локальным роутером `Tier 1` ONNX для мгновенного вызова за 0 токенов).
3. **`schema.input.json`** — JSON Schema (Draft 2020-12) входных аргументов (проверяется до старта скрипта).
4. **`schema.output.json`** — JSON Schema (Draft 2020-12) выходных данных (проверяется после завершения скрипта и гарантирует совместимость со следующим узлом графа).
5. **`main.csx` / `main.py` / `main.js`** — точка входа детерминированного ETL-скрипта.
6. **`tests/sample.fixture.json`** — эталонный тест (`sampleInput` ➔ `expectedOutput`), который обязательно прогоняется в песочнице перед сохранением скрипта в базу.

### 5.2. Каскадные и зависимые задачи (Mini-n8n DAG) с ИИ и Human-in-the-Loop:
* **Последовательные и параллельные узлы:** Узлы `SkillNode`, `NetrunnerScriptNode`, `ConditionNode`, `ParallelFanOutNode`, `JoinNode`, `LlmProcessNode`, `HitlApprovalNode`, `DeliveryNode` объединяются в направленный ациклический граф (`NetrunnerWorkflowDefinition`).
* **Точечный ИИ внутри каскада (`LlmProcessNode`):** ИИ может стоять между двумя детерминированными скриптами, получая уже очищенный от мусора JSON и возвращая типизированный `Structured Output` под контролем `TokenBudgetGovernor`.
* **Human-in-the-Loop (`HitlApprovalNode`):** Для задач, требующих подтверждения владельца, выполнение графа атомарно сохраняется в `data/subsystems/netrunner.db` (`Status = WaitingForHumanApproval`), освобождая потоки CPU/RAM, и возобновляется ровно с того же шага после нажатия кнопки `[✅ Одобрить]` в Telegram или Desktop UI (даже после перезагрузки ПК).
