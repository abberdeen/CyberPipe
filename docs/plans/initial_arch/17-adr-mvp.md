# 17. Реестр решений (по ответам владельца 2026-10-19)

Канонические решения. Полный журнал: [DECISIONS.md](../DECISIONS.md).
Термин «MVP» здесь и далее не означает ограничение объёма: реализуется всё из планов, кроме явно помеченного как потенциальное.

## ADR-001. Хранение: одна PostgreSQL + pgvector
- **Решение:** только PostgreSQL с расширением pgvector. Одна база на проект, таблиц сколько угодно.
- Отдельных мелких баз нет: PostgreSQL, шифрование на уровне PostgreSQL/диска, отдельные `*` (PostgreSQL) по подсистемам, реестр подсистемных БД — удалены из архитектуры.
- Векторы эмбеддингов хранятся в pgvector; полнотекстовый и семантический поиск — в той же базе.
- Если приложение не смогло само запустить/подключиться к БД — попросить пользователя восстановить подключение, спросить пароль от БД (Q21). Ничто не хранится только локально в файлах.

## ADR-002. Шина и планировщик
- Обмен сообщениями пишется только через **собственные интерфейсы проекта** (ремонтопригодность): бизнес-логика не зависит от конкретной реализации транспорта, реализация заменяется без переписывания логики. Конкретный внешний брокер в планах **не указывается и обязательным не является**; транспорт по умолчанию не фиксируется как продукт. Устаревшие формулировки про конкретную шину, её внутрипроцессный режим по умолчанию и отдельный enterprise-брокер из планов удалены (уточнение владельца 2026-10-19).
- **Планировщик: Quartz.NET** (не Hangfire — из-за его лицензионных ограничений, уточнение владельца 2026-10-19; возможна продажа: open-source + коммерческая модель, Q22). Данные Quartz.NET хранятся в той же PostgreSQL. Встроенного дашборда у Quartz.NET нет — расписания показываются и управляются в собственном Avalonia UI.

## ADR-003. Цепочки автоматизации: Trigger → Skill → Script → Delivery
- Термины «Mini-n8n», «n8n», «DAG», «workflow», «граф», «визуальный редактор» из планов удалены.
- Есть только цепочки вида **Trigger → Skill → Script → Delivery**. Таких цепочек может быть сколько угодно.
- Известные триггеры: **Webhook, Cron, function call, сообщение из чата**.
- Визуального редактора нет; цепочки описываются конфигурацией.

## ADR-004. Скрипты цепочек (skill-hack.*)
- Точка входа пакета — **`skill-hack.*`** (`skill-hack.csx`, `skill-hack.py`, `skill-hack.js` и т.п.), а не `main.*`.
- Каждый скрипт исполняется своим компилятором/интерпретатором.
- В `netrunner.manifest.json` обязательно указывать: `runtime.language`, `runtime.languageVersion`, `runtime.environment`, `runtime.environmentVersion`, `runtime.entrypoint` (файл `skill-hack.*`). Пример:

```json
"runtime": {
  "language": "CSharp",
  "languageVersion": "12.0",
  "environment": "Roslyn",
  "environmentVersion": "4.12.0",
  "entrypoint": "skill-hack.csx",
  "timeoutMs": 15000,
  "maxMemoryMb": null,
  "deterministic": true
}
```

- `maxMemoryMb` не имеет жёсткого значения по умолчанию (Q9): лимит задаётся настройкой пакета/пользователя.

> Примечание: шаблон манифеста и валидатор в `.agents/skills/netrunner-script-package/` лежат в read-only области и из этой сессии не правятся. Обновить их под `skill-hack.*` и новые поля runtime — отдельная задача при доступе на запись; до этого верен этот ADR.

## ADR-005. Платформы и каналы
- Один проект Avalonia, сборки под все ОС; фокус ручного тестирования — Windows (Q6).
- Каналы — все параллельно, без ограничений «только для первого этапа»: **Telegram (первый канал, позже добавляются новые), Avalonia Desktop, CLI** (Q4, Q19).

## ADR-006. Запуск: Service + Desktop (Q24)
- Установка в `Program Files`. **Service и Desktop — разные вещи.**
- Service (служба Windows) работает постоянно, может выводить нотификации.
- Desktop можно закрывать; из Desktop должен быть контроль Service: запуск / остановка / перезапуск и т.п.

## ADR-007. Модели (Q15, Q16, Q10)
- В приложение ничего не встроено, включая эмбеддинг. Приложение не связано с конкретными моделями.
- При первой установке предложить установку стандартного (желательного) эмбеддинга для Tier 1: мультиязычная модель (`multilingual-e5-small`, Q10-А).
- Остальные модели выбирает пользователь. В интерфейсе — инструмент установки и настройки локальных моделей для новичка: например, выбрал Qwen3 через Ollama — приложение само ставит и настраивает.
- Жёсткие каталоги 15 локальных + 8 облачных моделей сохранить, вести в виде JSON.

## ADR-008. Безопасность и прочее
- Изоляция воркера: Restricted Token + Job Object + Deny-ACL (Q13-Б), без ставки на AppContainer.
- Dev-инструменты (Git Radar, Build/Test Watchdog, DevToolProcessRunner) — **убраны полностью** (Q14).
- Фиксированный Volume Clamp заменён эвристической защитой: эмбеддинг оценивает риски контента и устройства вывода (наушники — свободно; мощная акустика/сабвуфер ночью — отклонить) (Q17).
- SLO-цифры — цель («доска почёта»), а не ворота приёмки (Q11-А).
- Бюджеты по умолчанию (Q23-А): дневной кап $0.50, soft 4 000 / hard 12 000 токенов на задачу, 3 хода облака / 5 локально; всё в конфиге.
- Роль Guest (Q18) **убрана полностью**: только Owner, гостевых ролей и веток логики под них нет.

## Устарело этим реестром
- Прежние ADR-001 (собственная абстракция сообщений/PostgreSQL/MessageBroker), ADR-002 (раскладка `*` (PostgreSQL)), ADR-003 (шифрование на уровне PostgreSQL/диска) — заменены ADR-001/002 выше.
- Упоминания PostgreSQL/шифрование на уровне PostgreSQL/диска/Hangfire/Guest в остальных документах подлежат вычистке при ближайшей правке каждого документа; при расхождении верен этот файл и [DECISIONS.md](../DECISIONS.md).
