# Решения владельца по вопросам из 44-decision-questions.md

> Дата: 2026-10-19. Источник: [44-decision-questions.md](../analysis/agents/44-decision-questions.md).
> Статус: **принято**. При расхождении планов с этим файлом верен этот файл, пока не появится новое решение.
> Термины «MVP» в старых документах читать как «первый канал / первый этап поставки», а не как ограничение объёма: реализуется всё, что есть в планах, кроме явно помеченного как потенциальное.

| Вопрос | Решение |
|---|---|
| Q1 Канон | Объединить `initial_arch` + `arch-argon`. Остальные варианты (`arch-glm`, `arch-muse`, `arch-wonder`) — в `docs/plans/archive/`, не канон. |
| Q2/Q3/Q12 База данных | **Только PostgreSQL + pgvector. Одна база на проект**, таблиц сколько угодно. Никаких отдельных мелких БД и отдельных файловых баз по подсистемам нет. |
| Транспорт сообщений (уточнение 2026-10-19) | Конкретная шина/брокер в планах не фиксируется. Код пишется через собственные интерфейсы проекта, чтобы реализацию транспорта можно было заменить, не переписывая логику (ремонтопригодность). Формулировки с обязательным продуктом шины, режимом по умолчанию и enterprise-брокером удалены из канонических планов. |
| Q4 Объём | Проект не рассматривается как MVP. Реализуется всё из планов, кроме явно помеченного как потенциальное. Telegram — **первый** источник/канал, не единственный: позже добавляются новые каналы. |
| Q5/Q20 Автоматизация | Убрать упоминания «Mini-n8n», «n8n», «DAG», «workflow», «граф», «визуальный редактор». Есть только цепочка **Trigger → Skill → Script → Delivery**. Таких цепочек может быть сколько угодно. Известные триггеры: Webhook, Cron, function call, сообщение из чата. |
| Q6 Платформы | Один проект Avalonia, сборки под все ОС. Фокус ручного тестирования — Windows. |
| Q7/Q22 Планировщик | **Quartz.NET** (не Hangfire — из-за лицензионных ограничений, уточнение владельца 2026-10-19). Данные Quartz.NET хранятся в том же PostgreSQL. Встроенного дашборда у Quartz.NET нет — просмотр и управление расписаниями делаются в собственном Avalonia UI. |
| Q8 Скрипты цепочек | Точка входа — не `main.*`, а `skill-hack.*`. Каждый скрипт исполняется своим компилятором/интерпретатором. В `netrunner.manifest.json` обязательно указывать язык, среду исполнения и версию. |
| Q9 Лимит памяти песочницы | Жёсткий лимит 64 МБ убрать. Лимит задаётся настройкой. |
| Q10 Эмбеддинг Tier 1 | Вариант А: мультиязычная модель (`multilingual-e5-small`), пороги — по замеру на RU/EN командах. См. также Q15: модель не вшита, предлагается при первой установке. |
| Q11 SLO | Цифры (Tier 0 < 1 мс, /stop < 50 мс и т.п.) — цель и «доска почёта», а не ворота приёмки и не ограничения. |
| Q13 Изоляция | Вариант Б: Restricted Token + Job Object + Deny-ACL, без ставки на AppContainer. |
| Q14 Dev-инструменты | Убрать полностью. Скиллов Git Radar / Build-Test Watchdog и сервиса DevToolProcessRunner в проекте нет. |
| Q15 Модели | В приложение **ничего не встроено**, включая эмбеддинг. При первой установке предложить установку стандартного (желательного) эмбеддинга для Tier 1. Остальные модели выбирает пользователь. Приложение не связано с конкретными моделями, но в интерфейсе должен быть инструмент установки и настройки локальных моделей для новичка: например, выбрал Qwen3 через Ollama — приложение само ставит и настраивает. |
| Q16 Каталоги моделей | Жёсткие каталоги 15 локальных + 8 облачных сохранить, вести в виде JSON. |
| Q17 Защита звука/контента | Фиксированный Volume Clamp (60%/25%) заменить эвристической защитой: эмбеддинг оценивает риски — что за музыка/название, уместен ли контент, какое устройство вывода (наушники — без ограничений; мощная акустика/сабвуфер ночью — отклонить). |
| Q18 Guest | **Guest убран полностью** (уточнение владельца 2026-10-19). Только Owner. Никаких гостевых ролей, лимитов и веток логики под Guest в проекте нет. |
| Q19 Каналы | Telegram, Avalonia Desktop и CLI — все три, без ограничений «это только для MVP». Это не связанные вещи, развиваются параллельно. |
| Q21 Секреты/восстановление | Всё хранится в PostgreSQL, ничто не теряется локально. Если приложение не смогло само запустить/подключиться к БД — попросить пользователя восстановить подключение, спросить пароль от БД. |
| Q22 Распространение | Возможна продажа: open-source + коммерческая модель. |

| Q23 Бюджеты | Вариант А: дневной кап $0.50, soft-лимит задачи 4 000 токенов, hard 12 000, 3 хода облака / 5 локально — стартовые значения, все в конфиге. |
| Q24 Установка/запуск | Вариант Б: `Program Files` + служба Windows. **Service и Desktop — разные вещи**: Service работает постоянно и может выводить нотификации; Desktop можно закрывать. Из Desktop нужна возможность контролировать Service: запуск / остановка / перезапуск и т.п. |
